## pgvector 적재·멱등성

다른 로컬 PostgreSQL과 충돌하지 않도록 이 프로젝트 전용 pgvector DB를
`localhost:5433`에서 실행했다. 원격 Supabase는 변경하지 않았다.

```powershell
$env:DATABASE_URL='<local pgvector URL>'
python -X utf8 -m backend.rag.vector_store `
  --manifest data/experiments/b100-v7-baseline/manifest.jsonl `
  --chunks data/experiments/b100-v7-baseline/chunks.jsonl `
  --embedding-ids data/embeddings/v7/e5-b100-v7.ids.jsonl `
  --embedding-vectors data/embeddings/v7/e5-b100-v7.vectors.npy `
  --embedding-metadata data/embeddings/v7/e5-b100-v7.metadata.json `
  --batch-size 1000
```

같은 명령을 두 번 실행한 뒤에도 청크 수는 60,824개로 유지됐다. DB 직접
집계에서도 기업 100개, 문서 100개, 고유 `content_sha256` 51,495개,
임베딩이 있는 청크 60,824개, 벡터 차원 최소·최대 384를 확인했다.

## HNSW 검색·용량

- pgvector: 0.8.6
- 인덱스: `idx_chunks_embedding` (`hnsw`, `vector_cosine_ops`)
- 상태: `indisvalid=true`, `indisready=true`
- 회사·연도 SQL 필터와 `SET LOCAL hnsw.iterative_scan = relaxed_order`를 적용한
  cosine top-10 `EXPLAIN (ANALYZE, BUFFERS)`에서 `idx_chunks_embedding` 사용 확인
- 측정 실행 시간: 3.454ms

`ANALYZE chunks` 후 측정한 로컬 용량은 다음과 같다.

| 항목 | MiB |
|---|---:|
| DB 전체 | 422.12 |
| `chunks` 테이블+TOAST+인덱스 | 414.18 |
| `chunks` 전체 인덱스 | 132.26 |
| HNSW 인덱스 | 102.48 |

FY2025 100사만으로 기존 350MiB 목표를 72.12MiB 초과한다. 따라서 W2.1 적재
기능은 완료됐지만, 최종 100+30 코퍼스 전에 벡터 분리 테이블, 청크 범위 조정,
운영 DB 용량 상향 중 하나를 결정해야 한다.
