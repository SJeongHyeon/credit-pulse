# 저점수 그래프 1위 재검토: 키 없는 검증

## 이유

사용자 실측 164번 60번에서 그래프가 추가한 원문 청크가 검색 1위(점수 0.6203)였지만 기존 임계값 0.6767 미만이라 채점기가 호출되지 않았다. Supervisor가 거절을 골라 최종 답변은 두 모드 모두 `ITEM_NOT_DISCLOSED`였다. 62번은 그래프 후보가 최종 top-10에 없고 검색 1위·점수가 두 모드에서 같아 작성기 흔들림 가능성이 크다.

## 변경

`GRAPH_LOW_SCORE_REVIEW` 기본값은 `false`다. 켜면 그래프에서 새로 온 청크가 최종 검색 1위이고 임계값 미만인 경우에만 기존 검색 채점기를 최대 1회 호출한다. 채점기가 1위 청크를 관련 근거로 고르고 충분하다고 할 때만 작성으로 간다. 부족·오류·키 없음이면 거절을 유지한다. 그래프를 끈 서비스 경로는 변하지 않는다.

150번 저장 기록에서 이 조건의 후보는 60번(관련, 0.6203)과 26번(비관련, 0.4579)이다. 이 둘만으로 일반화할 수 없어 실제 평가가 필요하다. 임계값·모델·코퍼스·그래프 인접 구조·검색 후보 상한은 바꾸지 않았다.

## 확인

- `python -m pytest -q tests/test_document_graph.py tests/test_retrieval_combo.py tests/test_supervisor_flow.py tests/test_supervisor_graph.py tests/test_trust_boundary.py`: 182 passed.
- `git diff --check`: 통과.
- 실제 API 키 호출 없음. 60·26·62번 소수 탐침과 전체 평가가 남아 있다.

**판정:** 동작 시험만 통과했다. 품질·속도 개선은 아직 실측하지 않았으므로 `GRAPH_RETRIEVAL_ENABLED=false`와 `GRAPH_LOW_SCORE_REVIEW=false`를 유지한다.

## 소수 탐침 실측

사용자가 이전에 안내한 60·26·62번의 끔/켬 비교를 진행하도록 승인했다. 60번 2회는 완료됐고, 26번 단독 실행은 평가 도구가 관련 문항 0개일 때 검색 지표를 계산하지 못해 결과 파일 없이 중단됐다. 26·62번을 묶은 2회 실행으로 마쳤으며 60번은 재호출하지 않았다. 성공한 네 평가 실행(총 6문항)의 **기록된 비용 합계는 $0.031808**이다. 실패한 26번 단독 실행의 외부 호출 비용은 요약 파일이 없어 확인할 수 없으므로 실제 총액은 이보다 높을 수 있다.

| 문항 | 재검토 끔 | 재검토 켬 | 관찰 |
|---|---|---|---|
| 60 | 정답 청크 인용, 11.66초 | 채점기가 1위 그래프 청크를 충분하다고 봐 정답 청크 인용, 7.57초 | 두 모드 모두 답했다. 켠 쪽의 개선이라고 할 수 없다. |
| 26 | `ITEM_NOT_DISCLOSED` 거절, 13.32초 | 같은 거절, 10.87초 | 확장 청크는 최종 1위가 아니라 신규 분기를 타지 않았다. |
| 62 | 정답 청크 인용, 6.76초 | 정답 청크 인용, 5.73초 | 점수가 임계값 위여서 신규 분기를 타지 않았다. 답의 수치 정확성은 인용 지표와 별개다. |

60번 재검토를 켠 실행에서는 `graph_low_score_reviewed=true`, `graded=true`, `sufficient=true`가 기록됐다. 끈 실행에서는 채점 없이 `sufficient=false`였지만 Supervisor가 작성으로 갔다. 따라서 **새 분기가 의도대로 호출되는 것은 확인됐으나, 최종 품질의 증분 효과는 확인되지 않았다.** 위 시간 차이는 각 1회 측정이므로 속도 개선으로 해석하지 않는다. 이전 150번에서 26번 그래프 1위였다는 기록은 후보 10개 모드이고, 이번 후보 1개 모드에서는 그래프 후보가 최종 top-10에 없다.

**최신 판정:** 소수 탐침만으로 사전 등록한 전체 정답·오답 인용 및 p95 채택 기준을 판정할 수 없다. 신규 분기는 기본 꺼짐, 그래프 검색도 기본 꺼짐으로 유지한다. 이 문서 앞의 「키 없는 검증」 판정은 실측 전 상태를 설명한다.
