# G6 Langfuse 트레이스와 평가 점수 연결 (2026-11-07)

**결론: 질문 한 건이 Langfuse 트레이스 하나로 남고, 그 안에 외부 호출(채팅·리랭크·임베딩)이 토큰·공급자 비용·지연과 함께 기록된다. 평가 러너는 문항별 응답 지표(0/1)를 그 문항의 트레이스에 점수로 붙인다.**

| 항목 | 값 |
|---|---|
| Langfuse | Cloud(us), 프로젝트 `creditpulse` |
| 어댑터 | `backend/services/tracing.py`(키가 있을 때만 langfuse import, 실패해도 응답은 그대로) |
| 기록 지점 | `backend/services/llm.py`의 채팅(시도마다)·임베딩·리랭크 호출, 서비스 `review-query`·`review-approval`, 평가 러너 `eval` |
| 남기는 것 | 질문, 결과·거절 사유·판정·인용 청크 id, 모델, 토큰, 공급자 비용(OpenRouter `usage.cost`), 지연. 프롬프트·청크 본문은 남기지 않음(P19 R7). Voyage 리랭크는 응답에 비용이 없어 토큰만(R4) |
| 점수 | `scripts/run_graph_eval.py`가 지표 계산 뒤 문항별 `correct_citation`·`wrong_citation`·`over_refusal`(관련), `correct_refusal`·`hallucination_risk`(비관련)를 트레이스에 붙임(`evals/response_metrics.py::per_question_flags`, 합이 집계 지표와 같음을 시험으로 확인) |

## 운영(Cloud Run)

Cloud Run에 `LANGFUSE_PUBLIC_KEY`·`LANGFUSE_SECRET_KEY`·`LANGFUSE_HOST`를 넣으면 배포 서비스의 질의·승인도 같은 프로젝트에 트레이스로 남는다(README 배포 절 환경변수 표).

## 추가 (11/7 오후): 세션·사용자, 중복 관측 제거

- 트레이스 단위 속성을 Langfuse v5 `propagate_attributes`로 붙인다. 서비스 `review-query`·`review-approval`은 `user_id`(내부 UUID)·`session_id`(심사 건 id)·태그 `service`, 평가 러너는 `session_id`=실행 이름·태그 `eval`.
- 확인: `--limit 4` 실행(`g6_session_check`)의 트레이스 4개가 모두 세션 `g6_session_check`로 묶였다(v2 observations API의 `sessionId`).
- 중복: anthropic SDK가 만든 `anthropic.messages.create` 관측이 기본 필터로 함께 내보내져 chat과 같은 토큰·비용(10건 $0.00868)이 두 번 잡혔다. 클라이언트를 `Langfuse(should_export_span=is_langfuse_span)`으로 만들어 이 어댑터의 관측만 내보낸다. 다시 돌린 `g6_filter_check` 실행은 관측이 eval·chat·rerank만 남았다.
