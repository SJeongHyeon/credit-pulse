# 그래프 후보 상한 1개: 키 없는 검증과 실측 중단

- 브랜치: `codex/graph-retrieval-adoption`.
- 사전 등록: `evals/PREREGISTER.md`의 「그래프 후보 상한 10 → 1」.
- 변경 변수: `GRAPH_EXPANSION_LIMIT=1`. 그래프 기본값은 꺼짐이다.

## 키 없는 확인

저장된 150번 실행의 첫 검색 ID를 현재 `data/service/chunks.jsonl`의 문서 그래프에 넣었다. 60번에서 상한 1의 첫 이웃은 `chunk-869d5c3ae1e3938dd10b930d`로, 이전 그래프 실험이 회수하고 인용한 정답 청크와 같다. 62번의 첫 이웃은 `chunk-12a8479fa144722a898ee8a1`이다. 이전 62번 오답 인용 청크 두 개는 첫 검색 후보에도 있었고, 정답 청크는 두 모드 모두 최종 검색 1위였다. 따라서 62번 오답을 그래프가 추가한 이웃의 직접 효과로 단정하지 않는다.

`python -m pytest -q tests/test_document_graph.py tests/test_retrieval_combo.py`: 45 passed. 상한 1에서 기존 RRF 49개와 그래프 이웃 1개가 리랭커에 전달되는 회귀 시험을 포함한다. 동결 평가셋과 기존 결과 파일은 수정하지 않았다.

### 저장된 전체 실행 재생

150번의 일상어 23건·동결 v2 50건에서 첫 검색 ID와 필터를 읽어 현재 코퍼스의 그래프를 다시 탐색했다. 저장된 그래프 후보 목록과 재생 결과의 불일치는 **0건**이었다. 후보가 실제로 추가된 검색 호출은 일상어 20건, 동결 v2 31건이다.

상한 1에서는 과거 상한 10 결과 중 일상어 최종 top-10의 이웃 17개·인용 3개, 동결 v2 최종 top-10의 이웃 9개·인용 1개가 후보에서 빠진다. 인용이 바뀔 수 있는 문항은 일상어 10·36번과 동결 v2 58번이다. 60번의 정답 이웃은 첫 번째이므로 남는다. 이는 기존 결과의 차이만 보여 주며 새 리랭킹·작성 결과를 예측하지는 못한다.

**속도상 한계:** 현재 조합은 이웃 10개를 넣을 때 기존 RRF 40개를, 이웃 1개를 넣을 때 기존 RRF 49개를 보존한다. 따라서 리랭커 입력은 여전히 최대 50개다. 저장된 코퍼스로 계산한 입력 문자 수는 일상어 전체 1,132,362 → 1,127,550자(−0.4%), 동결 v2 1,735,106 → 1,736,440자(+0.1%)다. 상한 1만으로 리랭커 호출량이나 p95가 크게 줄 것이라는 근거는 없다. 사전 등록한 지연 기대는 실측 전부터 이 구조적 한계가 확인됐으며, 기대값은 결과에 맞춰 수정하지 않는다.

### 다음 속도 실험의 키 없는 설계 자료

후속 실험에서 이웃 1개와 기존 RRF 후보 수를 함께 제한하면 실제 리랭커 입력량을 줄일 수 있다. 다음 표는 저장된 **그래프 후보가 있었던 호출**에서 원래 10개 모드와 비교한 입력 문자 수 변화다. 이 설계는 아직 코드나 사전 등록에 반영하지 않았다.

| 기존 RRF 보존 | 이웃 포함 최대 후보 | 일상어 입력 문자 | 동결 v2 입력 문자 | 과거 인용 중 후보에서 빠지는 수(일상어/v2) |
|---:|---:|---:|---:|---:|
| 40개 | 41개 | −18.0% | −17.9% | 4/1 |
| 44개 | 45개 | −10.2% | −10.0% | 3/1 |
| 46개 | 47개 | −6.4% | −6.0% | 3/1 |
| 48개 | 49개 | −2.4% | −2.0% | 3/1 |

41개 안은 속도 여지가 가장 크지만 인용 근거가 빠질 위험도 있다. 과거 인용이 빠진다는 사실이 새 답변의 오답을 뜻하지는 않고, 반대로 검색 시간 감소를 보장하지도 않는다. 현재 상한 1 실험이 끝나야 다음 변수를 사전 등록하고 구현한다.

## 실측 상태

사용자가 60·62번, 그래프 끔·켬의 총 4문항 실행과 비용 $0.10 상한을 승인했다. 첫 실행(60번 그래프 끔)은 Voyage 리랭커의 HTTP 401 인증 오류로 중단됐다. 결과 파일은 생성되지 않았다. 같은 키로 재시도하지 않았고 나머지 세 실행도 시작하지 않았다. OpenRouter 등 앞 단계에 호출이 있었을 수 있으나 실패한 실행의 사용량 요약 파일이 없어 실제 비용은 확인할 수 없다.

**판정:** 상한 1의 최종 품질과 속도는 아직 측정되지 않았다. `GRAPH_RETRIEVAL_ENABLED=false`를 유지한다. Voyage 키를 사용자가 갱신한 뒤 승인된 4문항을 다시 측정해야 한다.

사용자 직접 실행용 `scripts/run_graph_limit_smoke.py`를 준비했다. `--dry-run`은 키를 읽거나 API를 호출하지 않고 네 실행 계획을 출력하며 통과했다. 실제 실행은 사용자가 `python -X utf8 scripts/run_graph_limit_smoke.py`로 시작한다. 첫 오류에서 중단하고 기존 결과를 덮어쓰지 않으며, 성공한 각 실행의 기록된 비용과 인용 ID를 보여 준다. 기록된 비용 한도는 호출 전 청구액을 강제하는 하드 캡은 아니다.

사용자 실행도 첫 60번에서 Voyage HTTP 401로 중단됐다. Desktop 프로젝트의 `.env`와 이전 `graphrag` 작업 폴더의 `.env`는 Voyage 키 값이 서로 다르며, Desktop 파일의 수정 시각이 더 오래됐다. 키 값은 출력·기록하지 않았다. 스크립트에 `--env-file`을 추가해 사용자가 어느 자격증명 파일을 읽을지 명시할 수 있게 했고, 해당 옵션의 `--dry-run`을 키 없이 확인했다. 다른 파일의 키가 유효한지는 아직 확인되지 않았다.

## 사용자 직접 실측: 60·62번 각 1쌍

이전 작업 폴더의 자격증명 파일을 지정해 네 실행을 완료했다. 알려진 비용 합계는 **$0.028328**이며, 사용자의 $0.10 한도 안이다. 실측 파일은 `evals/results/graph50/graph164_smoke_q{60,62}_{off,limit1}.*`이다.

| 문항·모드 | 검색 1위 | 최종 답변 | 총 시간 | 리랭커 시간 |
|---|---|---|---:|---:|
| 60 끔 | 전기 표 | `ITEM_NOT_DISCLOSED` 거절 | 9.86초 | 2.13초 |
| 60 이웃 1개 | **정답 당기 표** | `ITEM_NOT_DISCLOSED` 거절 | 9.96초 | 1.68초 |
| 62 끔 | 정답 청크 | **오답 인용 1건** | 6.27초 | 1.72초 |
| 62 이웃 1개 | 정답 청크 | 정답 인용 1건 | 6.61초 | 1.64초 |

60번은 그래프 이웃이 정답 청크를 검색 1위로 올렸지만 리랭커 점수 0.6203이 기존 임계값 0.6767보다 낮았다. 검색 보고는 두 모드 모두 `sufficient=false`였고 Supervisor LLM이 두 번 모두 거절을 골랐다. 150번의 60번 실험과 검색 1위·점수는 같지만 당시에는 작성으로 이어졌다. 즉 현재 경로에서는 **검색 회수만으로 최종 답변 개선이 일어나지 않았다.**

62번은 두 모드 모두 정답 청크가 검색 1위이고 점수도 0.7885로 같았다. 그래프가 추가한 청크는 최종 top-10 밖이다. 끈 쪽 오답과 켠 쪽 정답 차이는 작성 단계의 흔들림 가능성이 크며, 그래프 이웃 1개의 인과 효과로 주장하지 않는다. 두 문항 모두 한 번씩만 쟀고 총 시간 차이는 외부 API 변동과 분리할 수 없다.

62번의 "정답 인용"은 평가기의 청크 일치 지표다. 후보 1개 모드의 답변은 차입금 1,698,370,521과 사채 종류별 금액을 열거했지만 질문이 요구한 차입금+사채 합계 1,827,858,248을 직접 제시하지 않고 확인 필요라고 썼다. 따라서 답변 내용 전체가 완전히 맞았다고 해석하지 않는다.

**현재 판정:** 상한 1은 60번 정답 근거를 검색에 넣었지만 답변 개선이나 속도 개선을 실증하지 못했다. 전체 평가를 추가 실행하지 않고 `GRAPH_RETRIEVAL_ENABLED=false`를 유지한다. 위의 이전 「실측 상태」 문단은 첫 두 실패 시점의 기록이며 이 절이 최신 상태다.
