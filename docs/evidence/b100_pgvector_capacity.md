# B 방식 FY2025 100사 pgvector 용량 실측

측정일: 2026-10-30
목적: 표 제목·헤더·여러 행을 1,000자 이내로 묶는 B 방식으로 FY2025 100건을 빌드하고, FY2024 비교 30건을 추가했을 때 350 MiB 이내인지 판단한다.

## 코퍼스 결과

| 항목 | 결과 |
|---|---:|
| 대상 문서 | 100건 |
| build 성공 / 실패 | 100 / 0 |
| eligible 청크 | 33,996 |
| eligible 고유 본문 SHA-256 | 32,467 |
| 청크 길이 중앙값 / 최댓값 | 817자 / 1,000자 |
| 원문·청크 자동 대조 | 3/3 PASS |
| 파서·표 청킹 | `dart_xml_v6`, `table_mode=group` |
| 임베딩 차원 | 384 (`intfloat/multilingual-e5-small`) |

- 표 청킹은 `table_mode=group`을 사용했다.
- 모든 문서가 `near_dup=false`, `superseded=false`이므로 이번 표본에서는 전체 적재와 eligible-only 적재가 같다.
- `data/targets.100.csv`는 기존 pilot과 같은 `sha256(corp_code)` 결정적 순서로 만든 용량 측정 표본이다. 최종 운영용 업종별 100사 목록은 별도로 확정해야 한다.

## 로컬 pgvector 실측

전용 PostgreSQL 16 + pgvector 데이터베이스에 33,996개 청크를 적재하고 `CHECKPOINT` 후 측정했다.

| 항목 | bytes | MiB |
|---|---:|---:|
| 빈 측정 DB | 8,150,039 | 7.77 |
| B-100 적재 후 DB 전체 | 181,967,895 | 173.54 |
| `chunks` 전체(테이블+TOAST+인덱스) | 173,793,280 | 165.74 |
| `chunks` heap | 44,212,224 | 42.16 |
| `chunks` TOAST | 49,963,008 | 47.65 |
| `chunks` 전체 인덱스 | 79,585,280 | 75.90 |
| HNSW 임베딩 인덱스 | 66,543,616 | 63.46 |

B 본문 고유 SHA-256 32,467개에 대응하는 실제 E5-small 384차원 float32 벡터를 생성해 33,996개 청크에 적재했다. 적재 계약에서 입력·저장 청크 수, chunks SHA-256, ids·vectors SHA-256과 벡터 차원을 검증했다. 앞서 용량만 먼저 확인한 재매핑 벡터 측정값과 최종 실제 벡터 측정값의 차이는 24,576 bytes(24 KiB)였다.

실측 뒤 파서 식별자를 `dart_xml_v6`으로 올려 같은 원문을 다시 빌드했으며 문서 100건, 청크 33,996개, 고유 본문 32,467개가 동일하게 유지됐다. 임베딩은 `content_sha256` 기준이므로 변경된 `corpus_id`·`chunk_id`와 무관하게 같은 본문 벡터를 재사용할 수 있다.

## 130문서 환산

빈 DB 고정비를 제외하고 100건 증가분을 1.3배 했다.

`7.77 + (173.54 - 7.77) × 1.3 = 223.27 MiB`

| 범위 | 예상 DB | 350 MiB 대비 여유 |
|---|---:|---:|
| FY2025 100건 실측 | 173.54 MiB | 176.46 MiB |
| FY2025 100건 + FY2024 30건 환산 | 223.27 MiB | 126.73 MiB |

회사·연도별 표 규모가 같다는 선형 가정이므로 최종 30건 적재 후 다시 측정한다.

## `bm25_tokens` 제거 실험

원본 DB를 복제하고 `bm25_tokens` 컬럼을 제거한 뒤 `VACUUM FULL ANALYZE`와 `CHECKPOINT`를 수행했다.

| 항목 | 결과 |
|---|---:|
| 컬럼 유지 DB | 173.56 MiB |
| 컬럼 제거 DB | 172.26 MiB |
| 관측 절감 | 1.30 MiB (0.75%) |
| 컬럼 제거 시 130문서 환산 | 221.61 MiB |

현재 `bm25_tokens`는 빈 배열이며 직접 payload 합계도 약 0.42 MiB뿐이다. 복제본의 1.30 MiB 차이에는 `VACUUM FULL` 과정의 HNSW 재구성 차이도 포함되므로, 용량만을 이유로 컬럼을 제거할 필요는 없다.

## 후속 작업

1. 업종 분포를 반영한 최종 FY2025 100사와 FY2024 비교 30사 목록을 확정한다.
2. 최종 130문서를 수집·빌드·적재한 뒤 350 MiB 기준을 다시 실측한다.
3. 자동 대조 3건의 DART 화면 사람 확인을 완료한다.
