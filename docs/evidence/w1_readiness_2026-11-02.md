# W1 수집·파싱 준비 상태 점검

점검일: 2026-11-02
범위: WBS W1.1~W1.12. W2 임베딩 적재는 실행하지 않았다.

WBS에는 W1.1이 250사로 남아 있으나 10/30 팀 합의와 현재 계약서는 FY2025
100사 + FY2024 30사다. 이번 점검에서 `SPEC.md`와 활성 Spec을 100+30으로
맞췄으며, WBS 원본 파일 자체는 수정하지 않았다.

## 결론

W1.2 파서와 W1.3 청킹을 점검하다가 ZIP 안 XML 블록을 문서 순서로 다시
번호 매길 때 `table_group`이 사라지는 결함을 확인했다. 이 때문에 서로 다른
표가 하나의 표처럼 묶였고, 기존 B-100 v6의 청크 수와 DB 용량 실측이 실제
"표 하나" 기준보다 작게 계산됐다.

`table_group`을 보존하고 파서 식별자를 `dart_xml_v7`로 올린 뒤 같은 B-100
원문을 다시 빌드했다. 문서 100/100과 원문 자동 대조 3/3은 통과했고,
`truncated=true`는 0건이 됐다. 다만 청크 수 증가로 기존 용량 실측은 다시
해야 한다.

- eligible 중 중복 본문: 9,329개

기존 v6 DB 실측을 청크 수에 단순 비례시킨 참고 추정은 FY2025 100사가
약 304.36 MiB, 100+30사가 약 393.33 MiB다. 이는 실측이 아니며 350 MiB
기준을 약 43.33 MiB 넘는다. 따라서 v7을 승인하면 W1.6 실제 임베딩·DB
적재를 다시 실행해 결정해야 한다.

## 팀 확인이 필요한 순서

1. "표 하나"의 경계를 보존하는 v7 수정과 청크 증가를 승인한다.
2. 업종 분포 FY2025 100사와 FY2024 비교 30사 목록을 확정한다.
3. v7 최종 130건을 수집·빌드하고 manifest·고유 해시를 갱신한다.
4. 원문 대조 3건의 사람 확인을 완료한다.
5. 그 뒤 W1.6 임베딩·pgvector 용량을 실측하고 W2 적재로 넘어간다.
