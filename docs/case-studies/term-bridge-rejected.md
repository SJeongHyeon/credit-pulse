# 사례 연구: 목차 어휘로 일상어 질문을 번역하자 놓친 문서를 되찾았지만, 지연 한도를 넘어 미채택한 일

**결정: 미채택(사전 등록한 규칙대로) · 기본 꺼짐 유지(`TERM_BRIDGE_ENABLED=false`) · 동결 v2는 측정하지 않음**

## 가설과 사전 기준

일상어로 물은 질문 3건(54·58·64번)을 놓친 이유는 질문의 말과 공시의 말이 달라서입니다. 추측하게 하지 않고, 그 회사 보고서의 **항목 이름 목록 안에서 최대 3개를 고르게** 하면 되찾을 것이라는 가설입니다(사전 등록 #152). 측정 전에 아래 기준을 먼저 정했고, **하나라도 어기면 미채택**입니다([`evals/PREREGISTER.md`](../../evals/PREREGISTER.md)).

① 놓친 3건 중 1건 이상 회수 · ② 동결 v2 누락 증가 0 · ③ 오답 인용 증가 0 · ④ 목록 밖 이름 0 · ⑤ 검색 단계 p50 +1.5초, p95 +3초 이하

## 측정(일상어 23문항, 1회)

| 지표 | 전(그래프만, 150번) | 후(+목차 어휘, 152번) | 사전 기준 |
| --- | --- | --- | --- |
| 첫 검색 Hit@10 | 20/23 | **22/23** | 1건 이상 회수 → 충족(54·64번) |
| 정답 / 오답 인용 | 18 / 4 | **20 / 1** | 오답 증가 0 → 충족 |
| 검색 단계 p50 | 1.73초 | **4.00초**(+2.3) | +1.5초 이하 → **불충족** |
| 검색 단계 p95 | 2.90초 | **6.36초**(+3.5) | +3초 이하 → **불충족** |
| 알려진 비용(23문항) | $0.165 | $0.262 | 기준 없음 |
| 7번 문항 Recall@10 | 1.00 | **0.25** | 부작용(1회라 흔들림과 구분 못 함) |

효과는 있었습니다. 그러나 질문마다 `gpt-4.1` 호출이 한 번 늘어 지연이 한도를 넘었고, 미리 정한 규칙대로 효과가 있어도 **미채택**입니다.

선택기 모델만 `gemini-3.5-flash-lite`로 바꾼 153번에서도 회수는 같았고(Hit@10 22/23) 비용은 $0.170으로 줄었지만, p50이 +2.05초로 한도(+1.5초)를 넘었습니다(p95는 +2.25초로 한도 안). 선택 호출이 질문마다 검색 앞에 직렬로 놓인 구조라 모델을 바꿔도 약 2초가 남았고, 역시 미채택입니다.

## 한계

- 일상어 23문항을 **1회** 측정한 결과라 회수 건수를 일반화하지 않습니다. 문항은 AI가 작성했습니다.
- 설계자가 54·58·60·64번을 본 뒤에 설계했습니다(누출 위험). 프롬프트와 목록 생성은 측정 전에 고정했지만 과적합 가능성이 남습니다.
- 항목 이름에 본문 문장이 장 제목으로 파싱된 것이 섞여 있어 파서 품질에 기대는 방식입니다.
- 동결 평가셋 v2는 측정하지 않았습니다. 그래서 서비스 기본 경로가 좋아졌다고 말할 수 없습니다.
