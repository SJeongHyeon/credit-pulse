# 검색 외부 API 지연 기록

## Why

- **페르소나**: 그래프 검색 속도와 품질을 검증하는 심사 시스템 개발자.
- **문제**: 검색 p95가 흔들렸지만 현재 결과의 리랭커 시간 밖 나머지에는 임베딩·BM25·벡터 검색이 섞여 있다. 외부 임베딩 호출 시간을 따로 기록하지 않아 안전한 개선 대상을 고르기 어렵다.
- **지표**: 호출별 임베딩·리랭커 API 지연, 검색 노드 시간, 리랭커 입력, 정답·오답 인용.

## Goal

- **성공 기준**: 성공한 OpenRouter 임베딩과 Voyage 리랭커 호출의 사용량 기록에 음수가 아닌 정수 `latency_ms`를 추가한다. 기존 벡터·점수·응답·비용 합계는 동일하다.
- **Out of Scope**: API 모델·재시도·시간 초과·후보 수·그래프 탐색 변경, 새 실제 키 시험, 실패 호출의 비용 추정.

## What

1. 외부 임베딩/리랭커 요청 직전부터 응답을 받은 직후까지 경과 시간을 잰다.
2. 기존 `llm_usage` 항목에 `latency_ms`를 추가한다. 질문·문서·키는 이 기록에 넣지 않는다.
3. 성공한 호출만 사용량 항목에 남긴다. 실패는 기존 오류 경로와 중단 정책을 유지한다.

## How

- `backend/services/llm.py`의 `openai_embeddings`와 `voyage_rerank`에서 `time.perf_counter()`로 시간을 재고 기존 `_record_usage`에 정수 밀리초를 전달한다.
- `scripts/run_graph_eval.py`의 질문별 `llm_usage` 보관 경로는 그대로 사용한다. 비용 집계는 기존 토큰·비용 필드만 사용한다.
- 외부 API를 호출하지 않는 모의 클라이언트 시험으로 응답과 사용량 스키마를 검증한다.

## AC (Given-When-Then)

- **AC-01** GIVEN 모의 OpenRouter 임베딩 성공 WHEN 호출 THEN 벡터 순서는 기존과 같고 사용량에 음수가 아닌 정수 `latency_ms`가 있다.
- **AC-02** GIVEN 모의 Voyage 리랭커 성공 WHEN 호출 THEN 점수 순서는 기존과 같고 사용량에 음수가 아닌 정수 `latency_ms`가 있다.
- **AC-03** GIVEN 키 없음 또는 API 오류 WHEN 호출 THEN 새 외부 호출이나 가짜 성공 사용량 항목을 만들지 않고 기존 오류를 낸다.
- **AC-04** GIVEN 기존 평가 요약 WHEN 지연 필드가 있는 사용량을 집계 THEN 비용·정답·검색 지표 계산 결과는 변하지 않는다.
