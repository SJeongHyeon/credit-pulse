# 심사 건 상세 화면 시각 정렬

## Why

- 상세 화면만 남색 로고를 어두운 상단 바에 놓고, 공유 글꼴을 불러오지 않아 첫 화면·심사 건 목록과 색·글꼴이 다르다.
- 상세 카드에는 밝은 배경과 밝은 글자가 섞여 읽기 어렵고, 승인 항목의 제목이 박스 경계 밖에 걸친다.

## Goal

- 상단 로고·본문·제목 글꼴·카드 색을 첫 화면과 심사 건 목록의 공유 테마에 맞춘다.
- 승인 항목의 이름(알 수 없는 항목의 「알 수 없음」 포함)이 카드 안에 보이고 320px 너비에서도 넘치지 않는다.
- 승인·질의·인용의 동작과 API 계약은 바꾸지 않는다.

## What

- 상세 화면은 목록 화면과 같은 흰 로고 파일, 로컬 글꼴 CSS, `ui-sans` 본문 클래스를 쓴다.
- 상세·결과·승인 카드는 어두운 유리 바탕에 밝은 본문, 금색 보조 정보와 읽기 쉬운 입력 필드를 쓴다.
- 승인 `fieldset`의 `legend`는 접근 가능한 이름을 유지하면서 박스 안의 첫 줄로 배치한다. 긴 이름과 검증 배지도 줄바꿈한다.
- 글꼴 파일을 못 읽는 환경은 공유 테마의 시스템 글꼴 대체 순서를 따른다.

## How

- `review_detail.html`의 자산·클래스를 `reviews.html`과 맞춘다.
- `review-detail.css`의 밝은 카드·남색/회색 글자 값을 공유 테마 토큰으로 교체하고, 승인 `legend`를 항목 안의 한 줄로 배치한다.
- 표시 문자열은 계속 `textContent`로만 넣고, 사용자 데이터는 CSS에 삽입하지 않는다.

## AC

- GIVEN 두 심사 화면의 HTML WHEN 로고·글꼴 링크·본문 클래스를 비교 THEN 같은 흰 로고, `fonts.css`, `ui-sans`를 쓴다.
- GIVEN 상세 화면의 카드·입력 WHEN CSS를 검사 THEN 어두운 바탕과 밝은 글자이며 승인 항목 제목은 카드 안쪽 여백에 놓인다.
- GIVEN 알 수 없는 항목 또는 긴 항목명 WHEN 승인 항목을 표시 THEN `legend` 텍스트가 보이고 박스 밖으로 넘치지 않으며 라디오·이유 입력을 계속 쓸 수 있다.
