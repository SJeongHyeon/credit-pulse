# Spec 검색 뒤 "근거 없음" 거절에도 참고 뉴스 (거절 범위 확대) + 뉴스 선별

관련: [refusal-news-search.md](./refusal-news-search.md), [refusal-news-display.md](./refusal-news-display.md). 이 문서는 refusal-news-search의 "검색 뒤의 거절(ITEM_NOT_DISCLOSED)은 뉴스 대상이 아니다" 결정을 **바꾼다**.

## Why

- **페르소나**: FY2025 사업보고서 근거로 여신 심사 초안을 검토하는 심사역
- **상황**: 11/12 서비스 화면 검증에서 코퍼스에 있는 회사(삼성전자)에 대한 "최근 반도체 투자 이슈" 질문이 검색까지 한 뒤 "답변할 수 없는 질문입니다. 해당 항목에 대한 공시 근거를 찾지 못했습니다."로만 끝났다. 코퍼스 밖 회사·연도는 뉴스가 붙는데, 같은 종류의 질문이 회사가 코퍼스에 있다는 이유로 뉴스를 못 받는다.
- **문제**: 심사역에게는 둘 다 "공시에서 못 찾은 업무 질문"인데 한쪽만 다음 단서(참고 뉴스)를 받는다.
- **측정 지표**: 검색 뒤 근거 없음 거절의 뉴스 호출 정확히 1회, 정상 답변 질문의 뉴스 호출 0회, 플래그 꺼짐 시 기존 결과와 동일.

## Goal

- **해결 목표**: 검색까지 하고 근거가 없어 거절된 질문(`ITEM_NOT_DISCLOSED`)도 뉴스 참고 1회를 붙인다. 뉴스는 여전히 공시 근거가 아니다(`citations=[]`, `draft_items=[]`).
- **성공 기준**: AC-A1~A5 통과 / 턴당 뉴스 호출 ≤ 1 / 뉴스 항목 ≤ 5 / 플래그 꺼짐 시 State·결과 불변.
- **Out of Scope**: 분류 LLM 추가 호출, "예측" 규칙 거절, 답변 가능한 질문에 뉴스 붙이기, 뉴스 LLM 요약.

## What (4번: 거절 범위 확대)

**Happy Path**: 질문이 입구 검사를 통과하고 검색·작성(또는 supervisor 판단)을 거쳐 `ITEM_NOT_DISCLOSED`로 거절되면, 그래프가 뉴스 노드를 한 번 거쳐 끝난다. `refusal_kind="work_related"`로 취급한다(주제 판정을 통과한 질문이므로 분류 호출 없음).

| # | 상황 | 처리 |
|---|---|---|
| EC-A1 | 검색 뒤 `ITEM_NOT_DISCLOSED` 거절, 플래그 켜짐 | 뉴스 노드 1회. 성공이면 `work_related_with_news` 멘트, 0건·오류·키 없음이면 `work_related_news_unavailable` 멘트 |
| EC-A2 | 정상 답변(`outcome=answered`) | 뉴스 노드 없음, 호출 0회 |
| EC-A3 | 플래그 꺼짐 | 새 분기·새 State 키 없음, 기존 거절 멘트 그대로 |
| EC-A4 | 이미 뉴스 노드를 거친 턴 | 다시 가지 않는다(`news_search`가 채워져 있음) |
| EC-A5 | 입구 거절(코퍼스 밖·주제 밖) | 기존 동작 그대로(검색 전 거절은 이전 규칙) |

**구현 위치(최소)**: `backend/graph/supervisor_flow.py`의 `route_from_supervisor`에 "거절 사유가 `ITEM_NOT_DISCLOSED`이고 검색을 한 번이라도 했으며 아직 뉴스를 안 거침"을 뉴스 노드로 보내는 조건을 추가한다. `backend/graph/build.py`의 뉴스 노드가 `refusal_kind="work_related"`를 State에 남긴다.

## What (3번: 뉴스 선별)

본문에만 회사가 언급되는 기사를 줄이는 방법(예: 회사명이 제목 또는 요약에 있는 기사만 남김)을 **사전 등록한 뒤 HUB로 측정**해서 채택 여부를 정한다. 기대치는 `docs/evidence/news_relevance_filter_2026-11-12.md`에 측정 전에 적는다. 채택하지 않으면 코드는 바꾸지 않는다.

**결과(11/12)**: D1(검색어 첫 낱말이 제목 또는 요약에 있는 기사만)은 10개 질문 모두에서 현재(C)와 결과가 같아 채택 기준 (a)를 통과하지 못했다. **채택하지 않았고 코드는 바꾸지 않았다.** 상세는 위 증거 문서.

## 시험 (tests/test_news_after_search_refusal.py)

- AC-A1: 코퍼스에 있는 회사 질문이 검색 뒤 거절되면 뉴스 1회, 항목 ≤5, `work_related_with_news` 멘트, `citations=[]`, 분류 호출 0회
- AC-A2: 뉴스 오류는 재시도 없이 폴백 멘트, `news_calls=1`
- AC-A3: 정상 답변 질문은 뉴스 호출 0회
- AC-A4: 플래그 꺼짐이면 뉴스 호출 0회, 새 State 키 없음, 기존 멘트
- AC-A5: 같은 스레드에서 다음 질문에 앞 뉴스가 새지 않는다
