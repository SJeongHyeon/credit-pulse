# F6 첫 요청 대기와 502·503·504 안내

## Why

- 심사역이 배포 주소를 처음 열 때 서버가 깨어나는 동안 응답이 늦을 수 있다. 첫 화면의 세션 확인은 닫힌 로그인 창 안에만 상태가 있어 대기를 알아보기 어렵다.
- 현재 로그인·심사 화면은 502·503·504를 대체로 같은 오류로 표시해 사용자가 잠시 뒤 재시도할지 판단하기 어렵다.
- 첫 요청의 진행 상태와 실패 원인을 화면에 분명히 보여 주는지 자동화 시험으로 확인한다.

## Goal

- 첫 화면의 최초 세션 확인 중 보이는 상태 문구를 제공하고, 응답 후 숨기거나 실패 안내로 바꾼다.
- 첫 화면·심사 건 목록·상세의 HTTP 502, 503, 504에 각각 다른 고정 안내 문구를 보여 준다. 서버 본문·입력값은 노출하지 않는다.
- 기존 401 로그인 이동, 일반 5xx, 네트워크 오류, 로그인 성공 후 이동 동작을 유지한다.
- 범위 밖: 백엔드 변경, 자동 재시도, API 상태 추정, 회원가입 기능 브랜치 변경.

## What

1. `/` 로드 직후 `/api/v1/auth/me`를 기다리는 동안 첫 화면에 연결 확인 문구가 보인다. 200·401이면 사라진다.
2. 세션 확인이나 로그인 요청이 502·503·504이면 각각 게이트웨이 문제, 일시적 서비스 이용 불가, 응답 시간 초과를 안내한다.
3. `/reviews`와 `/reviews/{id}`는 기존 로딩 영역을 사용한다. 최초 목록·상세 조회 또는 질문 응답의 502·503·504를 구분하고 재시도 가능한 화면 상태를 유지한다.
4. 기타 상태는 기존 문구를 사용한다.

## How

- 공통 정적 모듈에서 502·503·504의 고정 문구를 선택한다. 응답 JSON 본문은 사용하지 않는다.
- `login.html`의 히어로에 접근 가능한 상태 영역을 넣고 `login.js`가 최초 `/me` 요청 시작·완료 시 갱신한다. `landing.css`의 기존 폰트·색 토큰을 사용한다.
- `reviews.js`, `review-detail.js`는 기존 로딩·오류 영역에서 상태별 문구를 사용한다. 오류가 나도 다시 불러오기·재질문 흐름은 유지한다.
- 실제 Cloud Run이 어떤 코드로 응답할지는 제어하지 않고, 브라우저가 받은 HTTP 상태만 표시한다.

## AC

- GIVEN 첫 화면 최초 `/me`가 지연됨 WHEN 응답을 기다림 THEN 화면에 연결 확인 문구가 보인다.
- GIVEN 첫 화면 최초 `/me`가 200 또는 401 WHEN 완료됨 THEN 연결 확인 문구는 숨겨진다.
- GIVEN 502·503·504 응답 WHEN 로그인·목록·상세·질문 요청이 끝남 THEN 세 코드별 서로 다른 고정 문구가 보인다.
- GIVEN 응답 본문에 오류 세부값이나 입력값이 있음 WHEN 오류를 표시함 THEN 그 값은 화면에 보이지 않는다.
- GIVEN 401·500·네트워크 오류 WHEN 기존 흐름을 실행함 THEN 로그인 이동·일반 오류·네트워크 오류 처리가 유지된다.
