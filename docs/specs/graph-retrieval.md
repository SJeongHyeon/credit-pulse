# 원문 구조 그래프를 이용한 근거 후보 확장

## Why

- **페르소나**: FY2025 사업보고서 근거를 확인하는 기업여신 심사역.
- **상황·문제**: 현재 BM25·벡터 RRF와 리랭커는 질문과 비슷한 청크를 고른다. 일상어로 바꾼 23문항 중 4건에서는 첫 검색이 정답 근거를 놓쳤다(`EVAL_REPORT.md` 4-47~4-49). 관련 절에서 바로 앞뒤의 청크를 함께 보지 못한 경우를 별도로 검증한다.
- **측정 지표**: 첫 검색 Hit@10, MRR@10, 오답 근거 수, 관련 질문 지연 p95, 추가 리랭크 입력량. 기존 동결 v1·v2는 수정하지 않는다.

## Goal

- **목표**: 원문에 기록된 문서 구조만으로 청크 연결을 만들어 기존 검색 후보를 확장한다. 같은 코퍼스의 동일 질문에서 그래프 모드의 근거 회수와 회귀를 비교한다.
- **채택 기준**: 기존 검색이 놓친 일상어 4문항 중 최소 1건을 첫 검색 top-10으로 회수, 동결 v2 관련 문항 Hit@10 감소 0건, 다른 회사·연도·접수번호·장·주석으로 잘못 확장한 후보 0건, 리랭커 입력 50개 이하. 실제 결과가 미달이면 미채택으로 기록한다. 응답 품질은 기존 v2 지표 5개를 재측정해 악화 여부를 따로 보고한다.
- **Out of Scope**: LLM으로 개체·관계를 추출하는 지식 그래프, 커뮤니티 요약, 새 그래프 DB, 새 공시 수집·임베딩, 동결 평가셋 수정, 검색 이외의 LangGraph 흐름 변경, 새 API.

## What

**Happy Path**
1. 서비스가 이미 검증된 청크 파일을 읽을 때 각 청크를 문서 구조 그래프의 노드로 등록한다.
2. 같은 `corpus_id`·`rcept_no`·`chapter`·`section_path`·`note_no` 안에서 `ordinal` 차이가 정확히 1인 청크를 양방향 간선으로 잇는다. 번호 사이가 비면 연결하지 않는다.
3. 질의 시 기존 RRF 상위 5개를 시작점으로 최대 2간선을 탐색하고 중복을 제거한 후보를 최대 10개 고른다.
4. 기존 RRF 상위 40개와 추가 후보를 합쳐 기존 리랭커에 넘긴다. 최종 top-10과 인용 검사는 기존 계약을 따른다.

**Edge Cases**
| 상황 | 처리 |
|---|---|
| 그래프 모드 꺼짐 | 기존 검색 결과·호출 경로가 동일하다. |
| 같은 절 이름이 다른 회사·보고서에 있음 | `corpus_id`·`rcept_no`로 분리한다. |
| 장 또는 주석 필터가 있음 | 확장 후보에도 검색 전 필터를 적용한다. |
| `superseded=true` 또는 원문 ID 중복 | 대체된 청크는 그래프에 넣지 않고 중복 ID는 기동 실패 처리한다. |
| 이웃이 없거나 모두 기존 후보임 | 기존 RRF 후보를 그대로 최대 50개 리랭킹한다. |
| 그래프 파일과 검색 파일이 다름 | 별도 파일을 쓰지 않고 `build_retriever`가 확인한 청크 목록에서만 그래프를 만든다. |
| 후보의 필수 메타데이터가 없거나 본문이 비어 있음 | `ScoredChunk` 계약 오류로 실패하며 빈 검색으로 위장하지 않는다. 본문 해시 불일치는 기존 신뢰 경계가 처리한다. |

## How

- **API**: 신규 HTTP API 없음. 기존 `build_retriever`의 반환 호출 계약 `retriever(state) -> list[dict]` 유지.
- **설정**: `GRAPH_RETRIEVAL_ENABLED`는 `true` 또는 `false`, 기본 `false`. 다른 값은 시작 시 설정 오류. 검색 조합 `d3-55`의 기존 임베딩·토크나이저·RRF·리랭커·top-k는 유지한다.
- **데이터**: `backend/rag/document_graph.py`가 이미 읽은 청크 목록으로 인접 그래프를 만든다. 별도 영속 저장소·외부 API·LLM 호출 없음. 간선은 같은 문서 구조 그룹에서 `ordinal` 차이가 1일 때만 만든다. 탐색 순서는 RRF seed 순위, 홉 수, `ordinal`, `chunk_id`로 결정한다.
- **통합**: `backend/retrieval_combo.py`의 1차 RRF와 기존 리랭커 사이에서만 후보를 확장한다. 켠 경우 RRF 상위 40개를 반드시 보존하며, 추가 후보는 RRF에 없던 청크만 최대 10개. 총 입력 최대 50개. 후보는 현재 `SearchFilters`와 일치해야 한다. 최종 `rank`는 1부터 다시 붙이고 `retrieval_method`에 그래프 모드 여부를 구분한다.
- **신뢰 경계**: 그래프 노드는 원문 청크를 가리킬 뿐 사실을 생성하지 않는다. 회사·연도 결정적 검사, 본문 해시 검사, 프롬프트 인젝션 정제, 인용 검증은 기존 경로를 유지한다.
- **평가**: `evals/PREREGISTER.md`에 수치 기대와 회귀 위험을 먼저 기록한다. v1·v2 동결 파일 및 기존 결과를 수정하지 않는다. 일상어 23문항과 동결 v2를 같은 코퍼스·검색 설정으로 모드만 바꿔 실행한다. 기준선과 실험 결과·달라진 문항을 별도 새 결과 파일에 저장한다.

## AC (Given-When-Then)

- **AC-01** GIVEN 모드가 꺼진 동일 청크·질문 WHEN 검색 THEN 기존 후보 순서와 최종 청크 ID가 같고 그래프 확장은 0건이다.
- **AC-02** GIVEN 시작 청크와 같은 문서·절의 다음 청크가 RRF 후보에 없음 WHEN 모드를 켜서 검색 THEN 다음 청크가 리랭커 후보에 포함된다.
- **AC-03** GIVEN 같은 절 이름을 가진 다른 회사·접수번호·연도 청크 WHEN 그래프를 탐색 THEN 그 청크는 후보가 되지 않는다.
- **AC-04** GIVEN 장·주석 필터가 지정됨 WHEN 탐색 THEN 모든 후보가 필터에 일치한다.
- **AC-05** GIVEN 대체된 청크 또는 중복 청크 ID WHEN 그래프를 구축 THEN 대체된 청크는 빠지고 중복 ID는 명시적 오류다.
- **AC-06** GIVEN 50개 이상의 RRF 후보와 이웃 청크 WHEN 검색 THEN 리랭커 입력은 50개 이하이고 RRF 상위 40개는 보존된다.
- **AC-07** GIVEN 탐색할 이웃이 없음 WHEN 검색 THEN 기존 RRF 후보 최대 50개가 리랭커에 전달된다.
- **AC-08** GIVEN 허용되지 않는 모드 문자열 WHEN 설정을 읽음 THEN 기동이 명시적 설정 오류로 중단된다.
- **AC-09** GIVEN 동일 코퍼스의 동결 v2·일상어 23문항 WHEN 사전 등록한 두 모드를 재측정 THEN 문항별 Hit@10·MRR@10·응답 지표·지연·비용 차이가 기록되고 동결 해시는 불변이다.
