# Spec — 심사 초안의 체크리스트 항목 표시

## Why

- **페르소나**: 사업보고서 근거를 확인하고 초안을 승인하는 기업여신 심사역.
- **상황**: 질문 API는 체크리스트 코드를 넘기지 않는다. 작성기가 질문 문장을 `item`으로 사용하고, 화면은 정해진 6개 코드 외에는 「알 수 없음」으로 표시한다.
- **문제**: 차입금·주요 고객처럼 명확한 항목의 초안도 이름을 알 수 없고, 승인하면 질문 문장이 메모 항목으로 저장된다.
- **측정 지표**: 6개 명확한 단일 주제 질문의 초안·승인 대기·저장 메모에서 항목 코드 일치 6/6, 키 없는 데모 기록 재생 회귀 0건.

## Goal

- **해결 목표**: 명확한 단일 체크리스트 질문의 초안을 승인 대기 직전에 SPEC §3.1의 코드로 정리한다.
- **성공 기준**: 6개 항목을 각각 정확히 표시하고 승인 요청·메모에도 같은 코드를 쓴다. 원래부터 명시된 체크리스트 코드는 유지한다.
- **Out of Scope**: 검색·작성 모델의 질의/프롬프트 변경, 여러 주제가 섞인 질문의 임의 판정, 고객·자회사 구분이나 답변 품질 수정, 기존 승인 대기 체크포인트의 마이그레이션.

## What

1. 질문과 같은 문자열을 `item`으로 쓴 단일 초안에서만, 질문에 하나의 체크리스트 주제가 명확하면 해당 코드로 바꾼다.
2. 소송, 보증·담보, 거래처 집중, 환율·원자재, 차입 구조, 우발부채를 각각 결정적인 표현으로 식별한다.
3. 주제가 없거나 둘 이상이면 원래 `item`을 유지한다. 화면의 「알 수 없음」은 알 수 없는 값에 대한 기존 안전 표시로 남긴다.
4. 명시적으로 전달된 `checklist_items` 및 여러 초안은 그대로 둔다.

## How

- `backend/graph/checklist.py`에 질문→단일 코드 판별 함수를 둔다. 분류에 LLM·검색·DB를 호출하지 않는다.
- `approval_prepare`가 `draft_items`를 저장하기 전에, 단일 초안의 `item`이 질문 문장과 같을 때만 판별 결과를 적용한다. 이 시점은 작성기와 verifier 뒤이므로 외부 호출 입력과 데모 기록 해시가 유지된다.
- `human_approval` payload, API 응답, 승인 요청 검증, `review_memos.items`는 같은 정리된 코드를 사용한다.
- 불명확한 질문은 잘못된 체크리스트 항목으로 강제하지 않는다.

## AC (Given-When-Then)

- **AC-01** GIVEN 6개 단일 주제 질문과 질문 문장을 `item`으로 가진 초안 WHEN 승인 대기에 들어갈 때 THEN 각각 SPEC §3.1 코드가 payload에 나온다.
- **AC-02** GIVEN 질문에 차입금과 담보가 함께 있거나 해당 주제가 없을 때 WHEN 승인 대기에 들어갈 때 THEN 질문 문장을 임의 코드로 바꾸지 않는다.
- **AC-03** GIVEN 호출자가 `checklist_items`를 명시하고 초안에 그 코드를 썼을 때 WHEN 승인 대기에 들어갈 때 THEN 원본 항목·순서가 유지된다.
- **AC-04** GIVEN 키 없는 기록 재생 질문 WHEN 초안 작성 호출이 일어날 때 THEN 외부 호출 입력은 기존 질문 문자열 `item`을 그대로 사용한다. 정리된 코드는 승인 대기 이후에만 보인다.
- **AC-05** GIVEN 정리된 초안을 심사역이 승인할 때 WHEN 메모를 저장할 때 THEN 승인 요청과 `review_memos.items`의 `item`이 같은 코드다.
