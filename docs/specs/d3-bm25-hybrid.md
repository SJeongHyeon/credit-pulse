# Spec — D3 BM25 하이브리드 실험

상태: **측정 완료, 판정 대상 2개 미채택** (2026-11-03). 아래 결정 D1~D5는 **팀장 확인 전 추천안 적용**이다.

## 결론

**문자 2-gram의 BM25 단독과 RRF는 둘 다 미채택이다.** 두 변형 모두 Recall@10이 0.667로 기준선 0.733보다 낮고 MRR@10도 기준 0.458에 못 미친다. 참고로 잰 **Kiwi + RRF는 Recall@10 0.867, MRR@10 0.474, 개선 7·악화 3으로 세 기준 수치를 넘었다.** 측정 전에 참고 변형은 판정하지 않기로 정했으므로 채택하지 않고, 별도 사전 등록이 필요한 후보로 W2.12에 넘긴다. 아래는 측정 전에 세운 계획이다.

회사·연도 필터 안에서 BM25 단독과 e5-small + BM25 결합(RRF k=60)을 재서 기준선과 비교한다. 판정 대상 토크나이저는 추가 패키지가 필요 없는 **문자 2-gram**이다. 공백과 Kiwi는 W2.12 담당에게 공유할 참고 값으로만 잰다.

## Why

- **페르소나**: 체크리스트 항목별 근거를 찾는 기업여신 심사역
- **상황**: 기준선 e5-small은 v1 관련 15건에서 Recall@10 0.733, MRR@10 0.408이다(PR #37).
- **문제**:
  1. 임베딩은 "차입금", "담보"처럼 공시에서 정확히 일치해야 하는 용어를 놓칠 수 있다.
  2. 강의 13 실습에서는 BM25가 임베딩보다 Recall·MRR이 높았다. 다만 그 정답셋의 결과이며 이 코퍼스에서 잰 적이 없다.
  3. SPEC §5의 검색 설계는 "형태소 BM25 + pgvector, RRF k=60"인데 근거가 되는 측정이 없다.
- **측정 지표**: Recall@10, MRR@10, 문항별 첫 정답 순위, 1위 적중 수, 토큰화 시간

## Goal

- **해결 목표**: 키워드 검색이 이 코퍼스에서 기준선을 이기는지 판단한다.
- **성공 기준(채택 기준)**: 변형별로 아래를 모두 만족하면 채택한다. 둘 다 만족하면 MRR@10이 높은 쪽을 고른다.
  1. MRR@10 **+0.05 이상** (0.458 이상)
  2. 기준선보다 첫 정답 순위가 나아진 문항이 나빠진 문항보다 **2개 이상 많음**
  3. Recall@10 **0.733 이상** (회귀 없음)
- **판정 대상**: 문자 2-gram의 BM25 단독, 문자 2-gram의 RRF. 2개뿐이다. 참고 변형이 기준을 넘어도 이 실험에서 채택하지 않고 W2.12로 넘긴다.
- **Out of Scope**: 형태소 분석기 확정(W2.12), `bm25_tokens` 적재와 pgvector 쪽 BM25, 그래프 연결, 리랭커 결합, RRF 가중치, k 튜닝, 질의 변경, 평가셋 변경, `backend/requirements.txt` 변경

## What

**Happy Path**

1. 평가셋 문항마다 `evals/filters_v1.jsonl`의 회사·연도 필터로 청크를 먼저 좁힌다.
2. BM25 단독은 좁힌 청크 안에서 점수를 계산해 상위 10개를 낸다.
3. RRF는 벡터와 BM25의 상위 50개 순위를 합쳐 상위 10개를 낸다.
4. 기존 `evaluate_files`로 채점해 결과와 지표를 저장한다.

**Edge Cases**

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 질의가 토큰을 만들지 못함 | BM25는 빈 결과 |
| EC-02 | 점수가 0 이하인 청크 | 질의 토큰이 맞지 않은 것이므로 결과에서 뺀다 |
| EC-03 | 점수 동률 | `chunk_id` 오름차순 |
| EC-04 | `near_dup`·`superseded` 청크 | 벡터 검색과 같이 제외 |
| EC-05 | RRF에서 한쪽 결과가 비어 있음 | 다른 쪽 순위만으로 합친다 |
| EC-06 | 필터에 맞는 청크가 없음 | 빈 결과 |
| EC-07 | 알 수 없는 토크나이저, 벡터 산출물 없는 RRF | 오류로 중단 |

## How

### 토크나이저 선택지

| 항목 | 공백 | 문자 2-gram (추천) | 형태소 Kiwi |
|---|---|---|---|
| 방식 | 공백으로 자름 | 낱말 안을 2글자씩 겹쳐 자름 | 형태소로 나눠 내용어만 남김 |
| 조사 처리 | 못 함. "담보"와 "담보를"이 다른 토큰 | 우회. "담보를" → 담보, 보를 | 분석으로 분리 |
| 의존성 | 없음 | 없음 | `kiwipiepy`, 모델 약 88MB(압축 파일) |
| 라이선스 | 해당 없음 | 해당 없음 | [Apache-2.0](https://github.com/bab2min/kiwipiepy/blob/main/LICENSE.txt) |
| 약점 | 한국어에 약함(P04 R1) | 토큰 수가 많고 뜻 없는 조각이 생김 | 설치·속도, 신조어·회사명 오분석 가능 |
| 강의 근거 | 3강 `tokenize_ws` | 3강 `tokenize_ngram` | 3강은 Okt를 다룸, Kiwi는 강의 밖 선택 |

**추천은 문자 2-gram이다.** 형태소 분석기 비교는 W2.12(류승민 담당) 범위라 이 실험에서 분석기를 정하지 않는다. 2-gram은 패키지를 늘리지 않고 조사 문제를 우회하므로 "BM25가 이 코퍼스에서 쓸모 있는가"만 묻기에 충분하다. 분석기 1종은 Kiwi로 골랐다. 자바가 필요한 Okt와 달리 pip만으로 설치된다.

Kiwi는 작업용 임시 환경에만 설치하며 저장소 의존성에 넣지 않는다. 남기는 품사는 일반·고유 명사(NNG, NNP), 어근(XR), 외국어(SL), 한자(SH), 숫자(SN), 동사·형용사 어간(VV, VA)이다.

### BM25 구현

- **`rank-bm25` 0.2.2를 쓴다.** [Apache-2.0](https://github.com/dorianbrown/rank_bm25/blob/master/LICENSE)이고 의존성은 numpy뿐이며 이미 `backend/requirements.txt`에 있다. 직접 구현하면 검증할 코드만 늘어난다.
- 변수는 `BM25Okapi` 기본값 k1=1.5, b=0.75다. 강의 13의 식과 같다.
- **IDF는 필터 안에서 계산한다.** 검색이 회사·연도 안에서만 일어나므로, 그 회사 안에서 흔한 말의 가중치가 낮아지는 것이 맞다. `(corp_code, fiscal_year, chapter, note_no)`별로 색인을 만들어 재사용한다.
- 라이브러리는 문서 절반 이상에 나오는 낱말의 IDF를 작은 양수로 바꾼다. 정확히 절반이면 IDF가 0이 되어 그 낱말만 맞은 문서는 EC-02로 빠진다.
- **알려진 한계**: 필터 결과가 아주 적으면(예: 청크 1개) 평균 IDF까지 음수가 되어 점수가 0 이하로 나오고 빈 결과가 된다. v1은 회사·연도 필터만 쓰고 회사당 청크가 144개 이상이라 이 측정에는 영향이 없다. 장·주석 필터를 붙일 때는 고쳐야 한다.

### RRF

- 식: `score(d) = Σ 1 / (60 + rank)`. 벡터와 BM25를 같은 무게로 합친다. 강의 6·13 방식이다.
- 점수를 직접 더하지 않는다. BM25 점수와 코사인 유사도는 척도가 달라서다(P04 R3).
- 양쪽 후보는 각 50개다. 리랭커 실험의 후보 수와 같고, 검색 계약의 상한은 100이다. 한쪽 목록에 없는 문서는 그쪽 기여가 0이다.

### 구조

- `backend/rag/bm25.py`: 토크나이저, `BM25Index`, `rrf_fuse`. 순수 계산만 둔다.
- `backend/rag/offline_eval.py`: `InMemoryBM25Backend`, `RRFBackend`, CLI `--retriever {vector,bm25,rrf}`, `--tokenizer`, `--rrf-k`, `--rrf-candidates`. 벡터 검색의 필터와 결과 변환은 공용 함수로 뽑아 두 백엔드가 같은 규칙을 쓰게 한다.
- `--retriever`를 주지 않으면 기존과 같은 벡터 검색이고, 결과는 커밋된 `emb_e5_v1.jsonl`과 바이트가 같아야 한다.

### 제약

- 동결 `evals/dataset_v1.jsonl`, 청크 `data/chunks.100-b-v7.jsonl`, `evals/filters_v1.jsonl`, k=10을 고정한다. e5 임베딩은 기준선과 같은 산출물을 쓴다.
- LLM을 부르지 않는다. 재시도나 루프가 없다.
- `data/` 아래 파일은 커밋하지 않는다.

## 측정 결과

동결 v1, 청크 v7, `evals/filters_v1.jsonl`, k=10. 기준선은 Recall@10 0.733, MRR@10 0.408, 1위 적중 4건이다.

| 역할 | 토크나이저 | 검색 | MRR@10 (≥0.458) | 개선/악화 (차이 ≥2) | Recall@10 (≥0.733) | 1위 적중 | 판정 |
|---|---|---|---:|---:|---:|---:|---|
| **판정** | 문자 2-gram | BM25 단독 | 0.411 ✗ | 6/5 ✗ | 0.667 ✗ | 4 | 미채택 |
| **판정** | 문자 2-gram | RRF | 0.426 ✗ | 3/5 ✗ | 0.667 ✗ | 5 | 미채택 |
| 참고 | 공백 | BM25 단독 | 0.193 | 1/10 | 0.400 | 2 | 판정 안 함 |
| 참고 | 공백 | RRF | 0.358 | 4/7 | 0.600 | 4 | 판정 안 함 |
| 참고 | Kiwi | BM25 단독 | 0.388 | 5/4 | 0.733 | 4 | 판정 안 함 |
| 참고 | Kiwi | RRF | 0.474 | 7/3 | 0.867 | 5 | 판정 안 함, W2.12로 넘김 |

BM25 단독 전체 실행 시간(청크 파일 읽기와 문항별 색인 포함)은 공백 1.2초, 2-gram 1.8초, Kiwi 23.3초다. 한 번 잰 값이다.

### 해석

- **2-gram은 얻은 만큼 잃었다.** 2-gram 단독은 14번을 살렸지만 4·12번을 잃었고, RRF에서는 14번을 다시 놓치고 7번을 잃었다. 원인은 분석하지 않았다.
- **RRF가 한쪽의 1위를 밀어낼 수 있다.** 4번은 벡터 1위였지만 Kiwi BM25 단독에서는 top-10 밖이었고, Kiwi RRF에서 6위로 내려갔다. 강의의 경고(P04 R5)와 같은 방향이다.
- **Kiwi RRF의 결과는 조심해서 읽어야 한다.** 관련 15문항이고, 변형 6개를 같은 평가셋에서 보고 고른 값이다. 참고 변형 사후 승격은 측정 전에 금지했다. 이 수치만으로 채택 근거가 되지 않는다.
- **9번은 어떤 변형으로도 구제되지 않았다.** 10번은 공백 토크나이저에서만 top-10에 들었다.

### 다음 단계 제안

W2.12 담당이 분석기를 비교할 때 Kiwi + RRF를 사전 등록한 판정 후보로 넣고, 가능하면 v2 평가셋으로 확인한다. 채택하려면 `kiwipiepy`를 의존성에 추가해야 하고, 품사 선택도 함께 정해야 한다.

### 측정 검증

- `--retriever`를 뺀 기본 실행 결과가 커밋된 `emb_e5_v1.jsonl` blob과 바이트까지 같다(sha256 `890b6f3f…`). 작업 트리 파일은 Windows에서 CRLF로 풀려 직접 비교하면 다르게 나온다.
- Kiwi RRF를 다시 실행해 결과가 같음을 확인했다. 다른 변형은 재실행하지 않았다.
- 지표 파일의 `dataset_sha256`은 모두 동결값 `8f79a754…`다.

## 결정 결과

모두 **팀장 확인 전 추천안 적용**이다. 뒤집으면 재측정이 필요하다.

| # | 결정 | 적용한 추천안 | 이유 |
|---|---|---|---|
| D1 | 판정 토크나이저 | 문자 2-gram | 패키지를 늘리지 않고 W2.12의 결정을 앞지르지 않는다 |
| D2 | 나머지 토크나이저 | 공백·Kiwi는 참고로만 측정 | W2.12에 공유할 자료다. 판정 대상을 늘리면 우연히 통과할 기회만 는다 |
| D3 | BM25 구현 | `rank-bm25` | 라이선스 확인 완료, 이미 저장소 의존성이다 |
| D4 | IDF 범위 | 필터 안 | 검색 범위와 통계 범위를 맞춘다 |
| D5 | RRF | k=60, 같은 가중치, 양쪽 후보 50개 | SPEC 기본값이다. 이 평가셋으로 조정하면 과적합이다 |

## AC (Given-When-Then)

**AC-BM-01 · 필터 안 검색**
- GIVEN: 두 회사에 같은 낱말이 있는 청크
- WHEN: 한 회사 필터로 BM25 검색
- THEN: 다른 회사 청크가 나오지 않고 `retrieve()` 계약 검증을 통과한다

**AC-BM-02 · 정렬과 제외**
- GIVEN: 점수 동률 청크, 질의와 겹치지 않는 청크, `near_dup` 청크
- WHEN: BM25 검색
- THEN: 동률은 `chunk_id` 오름차순이고, 겹치지 않는 청크와 `near_dup`은 결과에 없다

**AC-BM-03 · 조사 우회**
- GIVEN: 본문이 "담보를 제공"인 청크와 질의 "담보"
- WHEN: 문자 2-gram으로 검색
- THEN: 찾는다. 같은 입력의 공백 토크나이저는 찾지 못한다

**AC-BM-04 · RRF 계산**
- GIVEN: 순위 목록 `[a, b]`, `[b, c]`, k=60
- WHEN: 합침
- THEN: b가 1등이고 점수는 `1/62 + 1/61`이며, a와 c는 각각 `1/61`, `1/62`다

**AC-BM-05 · RRF 후보 수와 빈 목록**
- GIVEN: BM25가 빈 결과를 내는 질의
- WHEN: `--rrf-candidates 50`으로 RRF 검색
- THEN: 양쪽을 50개씩 요청하고, 벡터 순서대로 top-10을 낸다

**AC-BM-06 · 기존 동작 유지**
- GIVEN: `--retriever`를 주지 않은 실행
- WHEN: 기준선 명령 재실행
- THEN: 결과가 `evals/results/emb_e5_v1.jsonl`과 바이트까지 같다

**AC-BM-07 · 잘못된 입력**
- GIVEN: 알 수 없는 토크나이저, 또는 `--embedding-prefix` 없는 `--retriever rrf`
- WHEN: 실행
- THEN: 결과 파일을 쓰지 않고 오류로 끝난다
