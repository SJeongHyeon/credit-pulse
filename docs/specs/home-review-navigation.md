# 첫 화면 ↔ 심사 건 이동

## Why

- 심사역이 심사 건 목록이나 상세 화면에서 서비스 첫 화면으로 돌아갈 수 있는 링크가 없다.
- 기존 `/` 화면은 로그인된 세션을 곧바로 `/reviews`로 보내므로 로고에 링크만 걸어서는 이동이 되지 않는다.
- 첫 화면에서도 심사 건으로 돌아가는 경로가 보여야 한다.

## Goal

- `/reviews`와 `/reviews/{id}`의 로고를 누르면 `/`의 첫 화면이 열린다.
- 첫 화면의 「로그인」, 「보유 기업 보기」 오른쪽에 같은 알약 스타일의 「심사 건 확인」 링크를 둔다.
- 로그인 직후에는 기존처럼 `/reviews`로 이동한다. 이미 로그인한 상태에서 `/`를 방문하거나 새로 고치면 첫 화면에 머물고 로그인 버튼은 숨긴다.
- 범위 밖: 심사 건 API, 인증 쿠키, 로고 이미지, 배포 설정.

## What

1. 비로그인 사용자가 첫 화면에서 「심사 건 확인」을 누르면 같은 화면에서 「로그인 후 이용해주십시오」 안내창이 열린다.
2. 로그인한 사용자는 두 심사 건 화면의 로고를 눌러 `/`에 머물고, 「심사 건 확인」을 눌러 `/reviews`로 돌아간다.
3. 로그인에 성공한 사용자는 로그인 폼에서 `/reviews`로 이동한다.
4. 링크는 키보드로 접근할 수 있고, 기존 글꼴·색·버튼 크기를 따른다.

## How

- `reviews.html`, `review_detail.html`: 로고 이미지를 `/`로 가는 접근 가능한 링크로 감싼다.
- `login.html`: `.hero-actions`의 기존 두 컨트롤 뒤에 `href="/reviews"` 링크를 같은 `.pill.pill-ghost` 클래스로 추가한다.
- `login.js`: 최초 세션 확인 200은 홈 화면을 유지하고 로그인 버튼을 숨긴다. 로그인 제출 후 세션 확인 200은 `/reviews`로 이동한다. 401은 기존 로그인 흐름을 유지한다.
- `login.js`는 세션이 없는 상태에서 「심사 건 확인」의 기본 이동을 막고 안내창을 연다. `GET /reviews`는 기존 세션 검증을 통과한 요청에만 목록 HTML을 제공한다. 세션이 없거나 만료된 요청은 안내창을 여는 첫 화면으로 리다이렉트한다.
- `reviews.css`: 로고 링크에 키보드 포커스 표시를 준다. 기존 로고 크기는 유지한다.

## AC

- GIVEN `/reviews` 또는 `/reviews/{id}` WHEN 로고를 누르면 THEN `/`로 이동한다.
- GIVEN 로그인된 세션 WHEN `/`를 열면 THEN 리다이렉트하지 않고 첫 화면과 「심사 건 확인」이 보인다.
- GIVEN 로그인된 첫 화면 WHEN 「심사 건 확인」을 누르면 THEN `/reviews`로 이동한다.
- GIVEN 비로그인 첫 화면 WHEN 「심사 건 확인」을 누르면 THEN 첫 화면에서 「로그인 후 이용해주십시오」 안내창이 열린다.
- GIVEN 없거나 유효하지 않은 세션 WHEN `GET /reviews`를 직접 요청하면 THEN 심사 건 목록 HTML 없이 안내가 있는 첫 화면으로 이동한다.
- GIVEN 비로그인 첫 화면 WHEN 로그인을 완료하면 THEN `/reviews`로 이동한다.
- GIVEN 360px 폭과 키보드 사용자 WHEN 새 링크를 사용하면 THEN 버튼이 잘리지 않고 포커스가 보인다.
