# Spec - Rules Web UI (내 판정 규칙 보기·삭제)

G4(사용자별 장기 기억). 계약 근거: SPEC.md §6 `GET /api/v1/rules`·`DELETE /api/v1/rules/{id}`(PR #135), §3.5 Store namespace, WBS v4 결정(규칙 수정·메모 되돌리기는 빼고 삭제로 충족).

## Why

- **페르소나**: 기업여신 심사역. 승인 때 초안의 판정·사유를 고치면 그 내용이 다음 질의부터 자기 규칙으로 쓰인다(#114).
- **상황**: 잘못 고친 승인이 규칙으로 남으면 이후 모든 심사 초안에 그 틀린 지시가 들어간다.
- **문제**:
  1. 어떤 규칙이 저장됐는지 화면에서 볼 수 없다. API(`GET /api/v1/rules`)만 있다.
  2. 틀린 기억을 고치는 절차(가이드)가 화면에 없어, 심사역이 직접 지울 수 없다.
- **측정 지표**: 규칙 목록 확인 → 삭제 → 다음 질의의 `applied_rules`에서 빠짐을 자동화 테스트와 브라우저에서 각 1회 이상 확인한다. 화면에 다른 사용자 규칙·서버 오류 세부 정보 노출 0건.

## Goal

- **해결 목표**: 로그인한 사용자가 `/reviews` 화면의 「내 판정 규칙」 섹션에서 자기 규칙을 보고, 틀린 규칙을 지운다.
- **성공 기준**:
  1. `GET /api/v1/rules`의 `items`를 서버 순서대로 항목 라벨·지시·출처 메모와 함께 표시한다.
  2. 「삭제」 → 「정말 삭제」 두 번 눌러야 `DELETE /api/v1/rules/{rule_id}`를 보낸다. 204면 목록에서 뺀다.
  3. 규칙 메모리를 쓸 수 없는 배포(503 `SERVICE_UNAVAILABLE_RULES`, 데모 모드)에서도 심사 건 목록·생성은 그대로 동작한다.
  4. 이 화면의 자동화 테스트가 통과한다.
- **Out of Scope**: 규칙 수정(PATCH)·메모 되돌리기(`:revert`)(WBS v4에서 뺌), 규칙 직접 추가, 규칙 검색·정렬·페이지 넘기기(사용자당 최대 200건을 한 번에 받음), 심사 상세 화면의 규칙 표시, 별도 `/rules` 페이지, 백엔드 변경.

## What

### Happy Path

1. 로그인한 사용자가 `/reviews`에 들어온다. 화면은 세션 확인 뒤 심사 건 목록과 함께 `GET /api/v1/rules`를 불러온다.
2. 「내 판정 규칙」 섹션에 규칙마다 항목 라벨(예: 소송), 지시(승인 때 쓴 사유), 출처 메모 id, 「삭제」 버튼을 보인다.
3. 사용자가 「삭제」를 누르면 그 버튼이 「정말 삭제」로 바뀌고 「취소」 버튼이 나타난다.
4. 「정말 삭제」를 누르면 `DELETE /api/v1/rules/{rule_id}`(id는 인코딩)를 보내고, 204면 그 규칙을 목록에서 뺀다.

### Edge Cases

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 규칙 0건 | 「저장된 판정 규칙이 없습니다. 승인 때 판정·사유를 고치면 여기에 쌓입니다.」 |
| EC-02 | 목록 503 `SERVICE_UNAVAILABLE_RULES` | 「이 환경에서는 판정 규칙 기억을 쓰지 않습니다(데모 모드).」 섹션만 안내하고 심사 건 화면은 정상 동작 |
| EC-03 | 목록·삭제 401 | 로그인 화면(`/`)으로 이동 |
| EC-04 | 삭제 404 | 이미 없는 규칙이다. 목록에서 빼고 「이미 삭제된 규칙입니다.」 |
| EC-05 | 그 밖의 목록 실패(네트워크·5xx·429·형식 오류) | 섹션에 「판정 규칙을 불러오지 못했습니다.」(429는 요청 과다 문구). 심사 건 목록은 영향 없음 |
| EC-06 | 그 밖의 삭제 실패 | 규칙을 목록에 남기고 공통 문구(네트워크·5xx·429) 또는 「규칙을 삭제하지 못했습니다. 다시 시도해 주세요.」 |
| EC-07 | 「정말 삭제」 대기 중 「취소」 | 원래 「삭제」 버튼으로 돌아가고 요청을 보내지 않음 |
| EC-08 | 삭제 요청 중 연속 클릭 | 그 규칙의 버튼을 비활성화해 요청을 한 번만 보냄 |
| EC-09 | 알 수 없는 `item` 값 | 「알 수 없음」 라벨, 화면은 깨지지 않음 |
| EC-10 | 지시에 `<`, `&` 같은 문자 | 글자 그대로 보인다(HTML로 해석하지 않음) |

## How

- **화면 위치**: `backend/templates/reviews.html`의 심사 건 목록과 「새 심사 건 만들기」 사이에 `<section id="rules-section">`. 새 페이지·라우트는 만들지 않는다.
- **정적 자산**: `backend/static/reviews.js`에 규칙 목록·삭제 로직을 더한다. 항목 라벨은 `review-shared.js`의 `ITEM_LABELS`·`own`을 쓴다. 스타일은 `reviews.css`에 덧붙인다.
- **API 사용**
  - 목록: `GET /api/v1/rules` → 200 `{"items": [{"rule_id", "item", "instruction", "source_memo_id"}]}`.
  - 삭제: `DELETE /api/v1/rules/{encodeURIComponent(rule_id)}` → 204, 없음·남의 것 404, Store 없음 503.
- **흐름**: 세션 확인(`me`) 성공 뒤 심사 건 목록과 규칙 목록을 각각 불러온다. 규칙 목록 실패는 심사 건 목록 오류 영역을 쓰지 않고 섹션 안 `role="alert"` 영역만 쓴다.
- **보안 제약**: 서버 문자열은 `textContent`로만 넣는다(`innerHTML` 금지). 서버 오류 본문의 `message`·`details`·`request_id`는 화면에 쓰지 않고 상태 코드와 `error.code`만 본다. 브라우저 `confirm()`·`alert()`은 쓰지 않는다.
- **변경 파일 범위**: `backend/templates/reviews.html`, `backend/static/reviews.js`, `backend/static/reviews.css`, `tests/reviews_web_ui.test.mjs`, `tests/test_reviews_web_ui.py`, 이 Spec.

## AC (Given-When-Then)

**AC-01 · 섹션 제공**
- GIVEN: 브라우저
- WHEN: `GET /reviews`
- THEN: 「내 판정 규칙」 제목, 규칙 목록 영역, 섹션 안내 영역, 섹션 오류 영역(`role="alert"`)이 있다.

**AC-02 · 목록 표시**
- GIVEN: 로그인 상태이고 규칙 API가 규칙 2개를 반환
- WHEN: 화면이 열림
- THEN: 서버 순서대로 항목 라벨·지시·출처 메모와 「삭제」 버튼을 보인다.

**AC-03 · 빈 목록과 데모 모드**
- GIVEN: 규칙 API가 `items: []` 또는 503 `SERVICE_UNAVAILABLE_RULES`
- WHEN: 화면이 열림
- THEN: EC-01·EC-02 문구를 보이고, 심사 건 목록은 정상 표시된다.

**AC-04 · 두 단계 삭제**
- GIVEN: 규칙 하나가 표시됨
- WHEN: 「삭제」 → 「정말 삭제」, API가 204
- THEN: `DELETE /api/v1/rules/{인코딩된 rule_id}`를 정확히 한 번 보내고 그 규칙이 목록에서 사라진다. 「삭제」만 누르고 「취소」하면 요청이 없다.

**AC-05 · 이미 없는 규칙**
- GIVEN: 삭제 API가 404
- WHEN: 응답을 받음
- THEN: 그 규칙을 목록에서 빼고 「이미 삭제된 규칙입니다.」를 보인다.

**AC-06 · 삭제 실패 시 유지**
- GIVEN: 삭제 요청에서 fetch 예외·5xx·429 중 하나
- WHEN: 응답을 받음
- THEN: 규칙은 목록에 남고 해당 문구를 보이며 버튼이 다시 활성화된다.

**AC-07 · 세션 만료**
- GIVEN: 규칙 목록·삭제 중 401
- WHEN: 응답을 받음
- THEN: 로그인 화면(`/`)으로 이동한다.

**AC-08 · HTML 비해석**
- GIVEN: 지시가 `<img src=x onerror=alert(1)>`인 규칙
- WHEN: 목록에 표시
- THEN: 글자 그대로 텍스트로 보이고 요소로 만들어지지 않는다.
