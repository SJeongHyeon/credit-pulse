# 문서 그래프 후보 수 축소 실험

## Why

- **페르소나**: 사업보고서 근거를 확인하는 기업여신 심사역.
- **상황·문제**: 그래프 후보 최대 10개를 넣는 현재 모드는 일상어 23건 중 검색 누락 1건만 회수했고 동결 v2의 최종 오답 인용 1건과 검색 p95 증가를 보였다. 62번은 정답 청크가 두 모드 모두 1위였으므로 오답을 그래프 후보 탓으로 단정할 수 없다.
- **측정 지표**: 일상어 Hit@10, 최종 정답·오답 인용, 검색 p50·p95, 리랭크 입력 문자 수.

## Goal

- **성공 기준**: 후보 상한 1개로 60번의 회수를 유지하고, 동결 v2의 오답 인용을 기준선보다 늘리지 않으며 검색 p95가 그래프 10개 모드의 2,765ms 이하가 된다. 모든 수치는 같은 코퍼스·질문으로 재측정한다.
- **Out of Scope**: 문서 그래프 구조·평가셋·작성 모델·검증기 변경, 지식 그래프, 시각화, 기본 모드 켜기.

## What

1. `GRAPH_RETRIEVAL_ENABLED=true`이면 기존 확장 순서에서 최대 `GRAPH_EXPANSION_LIMIT`개의 이웃만 리랭커에 보낸다.
2. 환경값이 없으면 기존 상한 10개를 사용해 과거 실험을 재현한다.
3. 값은 정수 1~10만 허용하고 범위 밖·문자열은 기동 시 오류로 거절한다.
4. 그래프가 꺼져 있거나 적격 이웃이 없으면 기존 검색 후보를 그대로 보낸다.
5. 후보를 더할 때 전체 50개 상한과 원본 필터·청크 계약을 유지한다.

## How

- **API**: 기존 `retriever(state) -> list[dict]` 유지. 신규 HTTP API 없음.
- **설정**: `RetrievalSettings.graph_expansion_limit: int = 10`, 환경변수 `GRAPH_EXPANSION_LIMIT=1..10`.
- **통합**: `ComboRetriever`가 `DocumentGraph.expand(..., limit=min(graph_expansion_limit, rerank_candidates))`를 호출한다. 첫 검색과 리랭커·작성기·인용 계약은 유지한다.
- **평가**: `evals/PREREGISTER.md`에 먼저 등록하고 그래프 상한 10과 1을 비교한다. 동결 v1·v2와 기존 결과 파일은 수정하지 않는다.

## AC (Given-When-Then)

- **AC-01** GIVEN 그래프가 켜지고 적격 이웃 3개가 있음 WHEN 상한 1로 검색 THEN 첫 번째 이웃 1개만 리랭커에 전달한다.
- **AC-02** GIVEN 그래프가 켜지고 환경값이 없음 WHEN 설정을 읽음 THEN 상한은 10이다.
- **AC-03** GIVEN 상한이 0·11·문자임 WHEN 설정을 읽음 THEN 명시적인 설정 오류다.
- **AC-04** GIVEN 그래프가 꺼지거나 이웃이 없음 WHEN 검색 THEN 기존 후보 순서가 같다.
- **AC-05** GIVEN 같은 코퍼스의 두 상한 WHEN 평가 THEN 문항별 근거·인용·지연 차이를 기록하고 동결 해시는 변하지 않는다.
