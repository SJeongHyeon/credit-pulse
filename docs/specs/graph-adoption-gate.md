# 그래프 검색 40+1 후보의 기본 채택 판정

## Why

- **페르소나**: 공시 근거를 빠르고 정확하게 확인하려는 기업여신 심사역.
- **상황·문제**: 150번 실험에서는 예전 그래프 설정(이웃 최대 10개)을 그래프 끔과 전체 비교해 품질·속도 악화로 미채택했다. 이번 167번에서는 새 40+1 설정을 그래프 켠 상태끼리 비교했고 동결 v2 정답 인용은 늘었지만 검색 p95가 악화됐다. **새 40+1 설정**은 그래프를 끈 서비스 기준과 직접 비교한 기록이 없어 기본 채택을 판단할 수 없다.
- **측정 지표**: 동결 v2와 일상어의 정답·오답 인용, 첫 검색 Hit@10, 검색 p50/p95, 전체 응답 p50/p95, 리랭커 입력, 비용.

## Goal

- **성공 기준**: 그래프 켬 조건이 그래프 끔 조건보다 동결 v2·일상어에서 정답 인용을 각각 줄이지 않고 오답 인용을 늘리지 않으며, 적어도 한 평가셋의 정답 인용을 1건 이상 늘린다. 두 평가셋의 검색 p95는 각각 악화 0ms 이하이고 일상어 60번의 정답 근거 검색이 유지돼야 한다. 반복 측정에서도 같은 방향이어야 기본 채택을 검토한다.
- **Out of Scope**: 동결 입력·정답 변경, 모델·임계값·검색 점수 계산 변경, 그래프 시각화·프론트 통합, 현재 기본값 켜기.

## What

1. 같은 23개 일상어 질문과 50개 동결 v2 질문을 그래프 끔/켬으로 각각 실행한다.
2. 양쪽 모두 `GRAPH_RERANK_BASELINE_LIMIT=40`, `GRAPH_EXPANSION_LIMIT=1`, `GRAPH_LOW_SCORE_REVIEW=false`로 고정한다. 그래프 끔에서는 후보 한도 설정이 영향을 주지 않는다.
3. 각 결과는 5문항 이하 묶음별 별도 파일에 저장하고 성공한 묶음은 재사용한다. 관련 질문이 없는 v2 묶음은 만들지 않는다.
4. 전체 질문 수·동결 해시·서비스와 모델·비용을 기록한다. 품질이나 지연 기준 하나라도 실패하면 그래프 기본값은 꺼진 채로 둔다.

## How

- **실행**: `scripts/run_graph_limit_smoke.py --adoption-full`에서 `GRAPH_RETRIEVAL_ENABLED=false/true`만 바꾸는 30개 묶음을 만든다. 각 묶음은 `scripts/run_graph_eval.py`의 기존 도메인 검사·멀티 에이전트·노드 시간 측정을 쓴다.
- **결과**: `evals/results/graph50/graph168_full_*`에 저장한다. 기존 167번 결과와 동결 데이터는 읽기 전용이다.
- **키**: 실제 OpenRouter·Voyage 호출 전 범위·데이터·예상 및 최대 비용을 고지하고 별도 명시적 승인을 받는다.

## AC (Given-When-Then)

- **AC-01** GIVEN 일상어 23개와 동결 v2 50개 WHEN 드라이런 THEN 각 ID가 그래프 끔/켬 조건마다 한 번씩, 총 146회 계획된다.
- **AC-02** GIVEN v2 5문항 묶음 WHEN 요약 THEN 각 묶음에 검색 평가 대상 관련 문항이 최소 하나 있다.
- **AC-03** GIVEN 그래프 끔/켬 실행 WHEN 설정을 비교 THEN 그래프 플래그 외의 모델·코퍼스·질문·한도·임계값이 같다.
- **AC-04** GIVEN 일부 묶음 성공 후 오류 WHEN `--resume` THEN 완료 결과는 재사용하고 실패·미실행 묶음만 실행한다.
- **AC-05** GIVEN 전체 결과 WHEN 채택 판정 THEN 품질과 검색 p95 기준을 질문·평가셋별로 기록하고, 하나라도 실패하면 기본 그래프를 켜지 않는다.
