# G3 100사 고유 청크 수 독립 검증

## Why

- 평가자는 `data/manifest.jsonl`과 요약에 적힌 100사·31,967청크·고유 31,953청크를 보고도 전체 청크 파일이 없어 직접 다시 셀 수 없다.
- 16사 데모 스냅샷은 전체 100사의 G3 수치를 검증하는 입력이 아니다.

## Goal

- 100사 v9 청크를 압축 파일로 제공하고 평가자가 키·DB·원본 ZIP 없이 고유 청크 수를 독립적으로 다시 셀 수 있게 한다.
- 성공 기준: 문서 100건, 전체 31,967청크, eligible 본문 SHA-256 고유 31,953개, 기존 manifest·요약·해시 목록·청크 파일 SHA-256과 일치.
- 범위 밖: 코퍼스 본문 수정, 재청킹 설정 변경, 임베딩·벡터 재생성, 운영 배포.

## What

- `data/g3/chunks.100-b-v9.jsonl.gz`는 `data/manifest.jsonl`과 같은 100사·같은 코퍼스 ID의 전체 청크를 담는다.
- 평가자는 저장소를 받은 뒤 검증 명령 한 번으로 압축 파일 무결성, 문서별 청크 수, eligible 고유 본문 해시 수를 확인한다.
- 압축 파일이 없거나 해시·문서 수·본문 해시가 하나라도 다르면 검증이 실패한다.

## How

- 로컬 원본 ZIP 100건을 기존 manifest의 접수번호·회사코드·연도·수집시각·ZIP SHA-256과 대조한 뒤 v9 파서, fixed_window, 1,000자/100자, `embedding_model=unselected`로 재생성한다.
- 재생성한 manifest 및 청크 파일의 SHA-256이 `docs/evidence/g3_v9_manifest_100-b.md`의 기존 값과 같아야만 압축 파일을 만든다.
- 검증기는 gzip을 순차적으로 읽어 `content_sha256`, `near_dup`, `superseded`를 확인하고 문서별 수와 전체·고유 수를 다시 계산한다.
- 압축본 SHA-256은 증거 문서에 기록한다. 파일은 GitHub 일반 파일 한도 안의 압축본으로 제공한다.

## AC

- GIVEN 압축 청크와 manifest·요약, WHEN 검증 명령 실행, THEN 100/31,967/31,953 및 해시가 일치하고 종료 코드 0.
- GIVEN 압축 파일이나 한 행의 본문·해시가 변조됨, WHEN 검증, THEN 종료 코드가 0이 아니고 불일치 항목을 표시.
- GIVEN 16사 데모 스냅샷, WHEN 전체 G3 검증 입력으로 사용, THEN 100사 manifest와 문서별 수·해시가 달라 통과하지 못함.
