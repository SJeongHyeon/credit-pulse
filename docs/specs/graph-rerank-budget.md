# 그래프 검색의 리랭커 입력 후보 축소

## Why

- **페르소나**: 빠르고 정확한 공시 근거를 확인하려는 기업여신 심사역.
- **문제**: 그래프 이웃을 10개에서 1개로 줄여도 기존 RRF 후보가 40개에서 49개로 늘어 리랭커 입력은 여전히 50개다. 저장된 150번 기록 재생에서 이웃이 있는 검색의 입력 문자 수가 거의 줄지 않았다.
- **측정 지표**: 리랭커 입력 후보·문자 수, 검색 p50·p95, 전체 응답 p50·p95, 정답·오답 인용.

## Goal

- **성공 기준**: 그래프 이웃이 있는 질문에서 리랭커 후보 최대 41개, RRF 상위 40개와 이웃 1개 보존, 입력 문자 수 10% 이상 감소. 동결 v2 정답 인용 감소 0·오답 인용 증가 0, 일상어 60번 정답 근거 검색 유지, 검색 p95 악화 0ms. 기대 개선 폭은 실측으로 보고한다.
- **Out of Scope**: 모델·임계값·문서 그래프·초안·인용 검증·동결 평가셋 변경, 기본 그래프 모드 켜기.

## What

1. 그래프가 켜져 있고 적격 이웃이 1개 있으면 RRF 상위 40개와 이웃 1개를 리랭커에 보낸다.
2. 이웃이 없거나 그래프가 꺼져 있으면 기존 RRF 후보 최대 50개를 그대로 보낸다.
3. 설정이 없으면 기존의 총 50개 예산을 유지한다. 허용된 설정값은 정수 40~50이며 그 외 값은 기동 오류다.
4. 후속 리랭커 순위·최종 top-10·원문 인용과 회사·연도 필터는 기존 계약을 따른다.
5. 비교 질문의 두 회사가 각각 검색될 때도 회사별 후보 예산과 필터를 독립적으로 적용한다.

## How

- **설정**: `GRAPH_RERANK_BASELINE_LIMIT`는 비어 있으면 기존 동작, 설정하면 40~50. 실험은 40을 사용하고 `GRAPH_RETRIEVAL_ENABLED=true`, `GRAPH_EXPANSION_LIMIT=1`, `GRAPH_LOW_SCORE_REVIEW=false`를 양쪽에 고정한다.
- **통합**: `backend/retrieval_combo.py`의 RRF와 리랭커 사이에서, 이웃이 있을 때만 `min(rerank_candidates - graph_count, graph_rerank_baseline_limit)`개의 기존 후보와 그래프 후보를 합친다. 이웃이 없으면 기존 목록을 유지한다.
- **측정**: 기존 150번 로그는 위험 분석에만 사용한다. 새 결과는 별도 파일에 기록하고 동결 입력은 수정하지 않는다. 키 사용은 호출 서비스·전송 내용·비용을 고지하고 사용자 승인 뒤에만 한다.

## AC (Given-When-Then)

- **AC-01** GIVEN RRF 후보 50개와 새 그래프 이웃 1개 WHEN 한도 40을 켜서 검색 THEN 리랭커 입력은 RRF 상위 40개+이웃 1개, 총 41개다.
- **AC-02** GIVEN 적격 이웃 0개 WHEN 같은 설정으로 검색 THEN RRF 후보 최대 50개와 순서를 유지한다.
- **AC-03** GIVEN 그래프 검색 꺼짐 WHEN 한도 40이 설정됨 THEN 기존 경로와 최종 결과가 같다.
- **AC-04** GIVEN 설정 없음 WHEN 검색 THEN 기존 그래프 후보 결합 방식과 결과가 같다.
- **AC-05** GIVEN 설정 39·51·문자 WHEN 설정을 읽음 THEN 명시적 오류로 기동을 중단한다.
- **AC-06** GIVEN 같은 코퍼스·질문 WHEN 한도만 달리해 재측정 THEN 후보 수·문자 수·품질·지연과 동결 해시가 기록된다.
