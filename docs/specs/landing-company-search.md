# 랜딩 02 「기업 검색」 패널: 결과 목록·요약·정렬

## Why

- **페르소나**: 랜딩에서 보유 기업을 훑어보거나 특정 기업을 찾는 기업여신 심사역.
- **상황**: 랜딩 2페이지의 02 「기업 검색」 패널에는 입력칸과 예시 문구뿐이다. 검색 결과는 검색 버튼을 눌러 01 화면으로 돌아가야 볼 수 있다.
- **문제**:
  1. 패널이 비어 보이고 무엇을 검색할 수 있는지 알 수 없다.
  2. 입력해도 이 패널에서는 결과를 볼 수 없다.
  3. 최근 공시 기업을 훑어볼 방법이 없다.
- **측정 지표**: 02 패널을 열면 입력 전에도 보유 기업 100곳의 목록과 수치가 보이고, 입력하면 같은 패널 안에서 즉시 걸러진다.

## Goal

- **해결 목표**: 02 패널에 최근 공시 칩, 정렬 가능한 결과 목록(전체 스크롤), 요약 수치(검색 건수·공시일별 분포·최신 공시일·최다 공시일)를 채운다.
- **성공 기준**: AC 전부 통과 / `tests/*.test.mjs`와 pytest 통과(기존 실패 제외) / 새 API·새 라우트·차트 라이브러리 0개 / 가로 스크롤 없음.
- **Out of Scope**: 서버 검색 API, 심사 건 생성 연결, 기존 01 슬라이드 필터·검색 버튼의 01 이동 동작 변경, 로그인 필요 여부 변경(데이터는 `landing-data.js`의 공개 보유 기업 목록이므로 로그인 없이 동작), 정렬 선택 저장(새로고침하면 최신순으로 시작).

## What

### Happy Path

1. 02 패널이 열리면 제목 「기업 검색」, 한 줄 설명, 검색 입력, 왼쪽에 「최근 공시」 칩 3개와 목록, 오른쪽에 요약 수치가 보인다.
2. 목록은 전체 보유 기업을 공시일 최신순(같으면 가나다순)으로 보여 주며 고정 높이 안에서 스크롤한다.
3. 입력하면 이름·corp_code·별칭(`aliases`, 있을 때만) 부분 일치(NFKC 정규화·대소문자·공백 전부 무시, `landing.js` 슬라이드 필터와 같은 규칙)로 즉시 걸러지고, 제목은 「검색 결과 N곳」으로, 수치는 「N곳 검색됨」으로 바뀐다.
4. 칩을 누르면 그 기업명이 입력칸에 들어가 검색된다.
5. 정렬 드롭다운(아이콘 + 현재 정렬 + ▾)으로 최신순·오래된순·가나다순을 고른다.
6. 검색 버튼(제출)은 기존대로 01 보유 기업 화면으로 이동해 같은 검색어의 슬라이드를 보여 준다(`stage-tabs.js`·`landing.js` 그대로).

### 요약 수치

- 큰 숫자: 걸러진 기업 수(`N곳 보유` / 검색 중이면 `N곳 검색됨`), 아래 「보유 기업 100곳 중」.
- 「공시일별 기업 수」: 공시일마다 막대 하나, 높이는 최다 공시일 대비 비율(최소 6%). `role="img"`와 `aria-label`.
- 「최신 공시일」: 보유 기업 전체 중 가장 늦은 `filed_at`.
- 「공시가 가장 많았던 날」: 공시 기업 수가 가장 많은 날과 그 기업 수(동률이면 이른 날).

### Edge Cases

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 검색어가 공백뿐 | 전체 목록(입력 없음과 같음) |
| EC-02 | 검색 결과 0곳 | 목록 대신 「검색 결과가 없습니다.」, 수치는 0곳, 정렬 컨트롤은 유지 |
| EC-03 | 기업명에 HTML 문자열 | 모두 `textContent`로만 넣는다 |
| EC-04 | 정렬 메뉴가 열린 채 바깥 클릭·Esc·다른 항목 선택 | 닫히고, Esc·선택 후에는 포커스가 정렬 버튼으로 돌아온다 |
| EC-05 | 같은 공시일 | 가나다순으로 정한다(최신순·오래된순 모두) |
| EC-06 | 입력칸 지우기(x) 버튼 | `search` 이벤트도 `input`처럼 처리한다 |
| EC-07 | 데이터가 비어 있음(`COMPANIES` 길이 0) | 수치 0·「-」, 오류 없이 빈 목록 안내 |
| EC-08 | 모션 줄이기·좁은 화면 | 애니메이션 없음, 좁으면 한 열(수치가 목록 아래로) |

## How

- **마크업**(`login.html`의 `#stage-panel-1`): 기존 `.stage-search` 카드 안에 `h3`, `p.section-lead`, 기존 폼(`#company-search`, `#company-query`, `#company-search-submit` id 그대로)을 두고, 그 아래에 `#company-results`(왼쪽: 칩 `#cs-chips`, 제목 줄 `#cs-title` + 정렬 `#cs-sort`/`#cs-sort-menu`, 목록 `#cs-list`, 빈 안내 `#cs-empty`) 와 `aside#cs-summary`(오른쪽 수치)를 둔다. 상태 알림은 `#cs-status`(`role="status"`).
- **스크립트**: `company-search.js`가 `landing-data.js`의 `COMPANIES`를 그린다. 입력 `input`·`search` 이벤트를 듣는다(기존 `landing.js` 핸들러는 그대로 동작). 칩 클릭은 입력값을 바꾸고 `input` 이벤트를 보내 슬라이드 필터도 같은 검색어를 따르게 한다. DOM은 `createElement`+`textContent`만 쓴다.
- **정렬 메뉴**: `button[aria-haspopup="listbox"][aria-expanded]` + `ul[role="listbox"]`의 `button[role="option"][aria-selected]`. ↓로 열고 ↑↓로 이동, Enter·클릭으로 선택, Esc·바깥 클릭으로 닫는다.
- **스타일**: `company-search.css` 한 파일, `theme.css` 토큰만 사용(투명 흰색 오버레이 제외). 카드 높이는 목록 영역 고정 높이(10.6rem)로 유지하고 정렬·검색에 따라 변하지 않는다.
- **제약**: 새 API·라우트 없음, LLM 호출 없음, `innerHTML` 금지, 기존 01·03 패널과 슬라이드 동작 불변.

## AC (Given-When-Then)

**AC-01** · GIVEN 랜딩 02 패널, WHEN 처음 열면, THEN 보유 기업 100곳이 공시일 최신순으로 목록에 있고 첫 줄은 최신 공시 기업, 요약 수치(`100곳 보유`, 최신 공시일, 최다 공시일)가 보인다.

**AC-02** · GIVEN 목록, WHEN 「금」을 입력하면, THEN 이름·corp_code에 「금」이 들어간 기업만 남고 제목은 「검색 결과 N곳」, 수치는 「N곳 검색됨」이다. 공백·대소문자는 무시한다.

**AC-03** · GIVEN 칩, WHEN 누르면, THEN 입력칸에 그 기업명이 들어가고 목록이 걸러지며 `input` 이벤트가 발생해 슬라이드 필터도 같은 검색어를 따른다.

**AC-04** · GIVEN 정렬 드롭다운, WHEN 항목을 고르면, THEN 목록이 최신순·오래된순·가나다순으로 바뀌고 메뉴가 닫히며 포커스가 정렬 버튼으로 돌아오고 상태 알림이 바뀐 정렬을 알린다.

**AC-05** · GIVEN 열린 정렬 메뉴, WHEN Esc·바깥 클릭·↑↓Enter를 쓰면, THEN 각각 닫기·닫기·이동/선택이 된다. `aria-expanded`·`aria-selected`가 현재 상태와 맞는다.

**AC-06** · GIVEN 검색 결과가 0곳, THEN 목록 대신 「검색 결과가 없습니다.」가 보이고 수치는 0곳이다.

**AC-07** · GIVEN HTML 문자열을 담은 기업명, WHEN 렌더링, THEN 글자로만 보인다(`innerHTML` 미사용).

**AC-08** · GIVEN 검색 버튼(제출), THEN 기존대로 01 화면으로 이동한다(기존 `stage-tabs`·`landing` 테스트 통과).

**AC-09** · GIVEN 02 패널의 마크업·CSS, THEN 입력·폼·버튼 id가 유지되고 정렬 메뉴 속성(`aria-haspopup`, `role="listbox"`)이 있으며 CSS는 토큰만 쓰고 `prefers-reduced-motion`을 지킨다.

**AC-10** · GIVEN 이 변경, THEN `tests/company_search_web_ui.test.mjs`가 있고 `tests/*.test.mjs`와 pytest가 통과한다(기존 실패 제외).
