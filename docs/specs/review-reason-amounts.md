# 심사 초안 이유의 금액·회사 목록 표시

## Why

- 심사역이 승인 대기 초안의 이유를 읽을 때 `163,578,745` 같은 숫자의 단위를 알 수 없다.
- `회사명 금액 | 회사명 금액`이 한 줄의 일반 텍스트로 표시되어 회사명이 중간에서 끊긴다.
- 금액 오독이나 회사·금액 연결 오류 없이 원문과 대조할 수 있어야 한다.

## Goal

- 인용문에 단위가 명확한 금액은 원 단위 숫자로 표시한다. 예: `163,578,745`(천원) → `163,578,745,000원`.
- 회사·금액 목록은 각 회사를 하나의 표시 단위로 묶고, 너비에 따라 회사 단위로 줄바꿈한다.
- 범위 밖: LLM 답변·판정·근거·DB 원본 변경, 단위가 불명확한 숫자에 대한 추측.

## What

- 단일 숫자 또는 `|`로 구분된 회사·금액 목록의 숫자가 인용문에 있고, 관련 인용문의 단위가 하나로 명확하면 원으로 환산한다.
- 여러 회사는 고정 개수로 자르지 않고 사용 가능한 너비에 따라 배치한다. 한 회사명이 상자보다 길 때만 회사 내부에서 줄바꿈한다.
- 단위가 없거나 서로 다른 단위가 섞여 있거나 일반 서술문이면 원문을 그대로 표시한다.
- 승인자가 이유를 수정할 수 있으며, 단순 열람·승인만으로 저장할 원문 이유는 바꾸지 않는다.

## How

- 브라우저에서만 `draft.reason` 및 `draft.citations[].quote`를 읽어 표시용 금액을 만든다.
- 지원 단위는 인용문에 명시된 `원`, `천원`, `백만원`이다. 각각 1, 1,000, 1,000,000을 곱한다. 정수 계산은 `BigInt`를 쓴다.
- 단위가 명시되지 않았거나 여러 단위가 나타나면 환산하지 않는다. 숫자는 해당 인용문에 정확히 있어야 한다.
- 승인 대기 화면의 회사 목록은 텍스트 입력 대신 읽기 쉬운 묶음으로 먼저 보여주고, `이유 수정`으로 기존 입력란을 연다. 입력란은 회사마다 새 줄에서 시작한다.
- 승인 요청에는 수정하지 않은 이유의 원본을 보내고, 심사역이 바꾸었을 때만 편집된 내용을 보낸다.

## AC

- GIVEN `163,578,745`와 `(단위 : 천원)`을 포함한 인용문, WHEN 결과와 승인 초안을 표시, THEN `163,578,745,000원`이 보인다.
- GIVEN 3곳 이상 회사·금액 목록, WHEN 좁은 화면에 표시, THEN 회사·금액 묶음이 상자 너비에 맞춰 다음 줄로 이동한다.
- GIVEN 단위가 없거나 여러 단위의 인용문, WHEN 숫자를 표시, THEN 임의로 `원`을 붙이지 않는다.
- GIVEN 승인자가 이유를 고치지 않음, WHEN 승인, THEN API에는 원본 이유가 전달된다.
