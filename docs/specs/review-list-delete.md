# Spec - 심사 건 목록 삭제

## Why

- 심사역은 더 이상 필요 없는 심사 건을 한 건씩 또는 한 번에 정리할 수 있어야 한다.
- 측정: 삭제 확인 전 API 호출 0건, 삭제 성공 후 목록 잔존 카드 0건.

## Goal

- 내 심사 건 목록에서 개별 삭제와 전체 삭제를 제공한다. 전체 삭제는 목록에 아직 표시되지 않은 건도 포함한다.
- 성공 기준: 확인 취소 시 변경 없음, 확인 후 204면 카드 즉시 제거, 타인·없는 건은 동일한 404.
- Out of Scope: 판정 규칙 삭제, 다른 사용자의 기록 관리, 평가·검색·그래프 변경.

## What

1. 카드에 마우스를 올리거나 키보드로 초점을 옮기면 오른쪽 휴지통 버튼이 보인다.
2. 버튼을 누르면 `해당 심사건 내역을 삭제하겠습니까?` 대화상자와 `예`·`아니오`가 보인다.
3. `아니오` 또는 Escape는 닫기만 한다. `예`는 서버 삭제를 한 번 요청한다.
4. 204면 해당 카드만 제거하고, 마지막 카드였다면 빈 목록 안내를 보인다.
5. 401은 로그인 화면으로 이동한다. 실패하면 카드를 유지하고 정해진 오류 문구를 보인다.
6. 처리 중(`running`, `saving`)인 심사 건은 삭제하지 않고 409를 반환한다. 사용자는 나중에 다시 시도한다.
7. 전체 삭제 휴지통은 제목과 같은 행의 오른쪽 끝에 항상 표시한다. 버튼을 누르면 `전체 심사건 내역을 삭제하시겠습니까?`와 `예`·`아니오`를 표시한다.
8. `예`에 204가 오면 목록과 페이지 이동을 초기화하고 빈 목록 안내를 표시한다. 처리 중인 건이 하나라도 있으면 전체 삭제 요청을 취소하고 목록을 유지한다.

## How

- `DELETE /api/v1/reviews/{review_id}`: 인증된 사용자만 호출. 성공 204, 타인·없는 건 404 `RESOURCE_NOT_FOUND`, 처리 중 409 `CONFLICT_REVIEW_IN_PROGRESS`.
- `DELETE /api/v1/reviews`: 로그인 사용자 소유의 심사 건 전체에 적용한다. 빈 목록도 204다. 처리 중인 건이 하나라도 있으면 409 `CONFLICT_REVIEW_IN_PROGRESS`를 반환한다.
- 저장소는 사용자 조건과 행 잠금으로 대상 상태를 확인한다. 한 트랜잭션 안에서 잠근 심사 건의 메모에 연결된 규칙 이벤트, 메모, 심사 건 순서로 삭제한다.
- 3페이지 `reviews.html`, `reviews.js`, `reviews.css`에만 화면 제어를 둔다. 서버 오류 본문은 화면에 표시하지 않는다.

## AC

- GIVEN 내 심사 건 WHEN 카드에 hover 또는 focus THEN 휴지통 버튼이 보인다.
- GIVEN 확인창 WHEN `아니오` 또는 Escape THEN API 호출 없이 카드가 남는다.
- GIVEN 확인창 WHEN `예`와 204 응답 THEN 해당 카드가 즉시 사라진다.
- GIVEN 마지막 카드 WHEN 삭제 성공 THEN 빈 목록 안내가 보인다.
- GIVEN 타인 또는 없는 심사 건 WHEN DELETE THEN 동일한 404이고 다른 기록은 유지된다.
- GIVEN 처리 중인 심사 건 WHEN DELETE THEN 409이고 기록은 유지된다.
- GIVEN 제목과 심사 건 목록 WHEN 화면을 열면 THEN 전체 삭제 휴지통이 제목 오른쪽 끝에 표시된다.
- GIVEN 전체 삭제 확인창 WHEN `아니오` 또는 Escape THEN API 호출 없이 확인창이 닫힌다.
- GIVEN 여러 페이지에 걸친 내 심사 건과 다른 사용자의 심사 건 WHEN 전체 삭제 확인 THEN 요청 한 번으로 내 심사 건 전체가 삭제된다.
- GIVEN 처리 중인 내 심사 건이 하나 이상 WHEN 전체 삭제 확인 THEN 409이고 내 심사 건이 모두 유지된다.
