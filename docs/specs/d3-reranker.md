# Spec — D3 리랭커 실험

상태: **측정 완료, 미채택** (2026-11-03). 네 조합 모두 채택 기준을 통과하지 못했다. 재정렬 코드는 꺼진 상태로 남고 기본 검색에는 영향이 없다.

## 결론

**측정 결과 네 조합 모두 미채택이다.** 가장 좋은 ko-reranker + 짧은 표 합치기도 MRR@10 0.457로 기준 0.458에 못 미치고, 나아진 문항과 나빠진 문항이 5개씩 같으며, CPU 지연 p95가 59.2초로 기준 3초의 약 20배다. 아래는 측정 전에 세운 계획이다.

e5-small 상위 50개를 로컬 교차 인코더(cross-encoder)로 재정렬해 top-10을 평가한다. 후보는 `BAAI/bge-reranker-v2-m3`와 `Dongjin-kr/ko-reranker` 2개다. 리랭커는 순서만 바꾸므로 Recall@10의 상한은 **0.867**(13/15)이다. 9·10번은 top-100에도 정답이 없어 리랭커로 구제되지 않는다.

## Why

- **페르소나**: 체크리스트 항목별 근거를 찾는 기업여신 심사역
- **상황**: 베이스라인 e5-small은 v1 관련 15건에서 Recall@10 0.733, MRR@10 0.408이다(PR #37).
- **문제**:
  1. 정답이 후보 안에 있어도 순위가 낮다. MRR이 Recall의 절반 수준이다.
  2. 1·14번은 정답이 28·29위에 있어 top-10에 들지 못한다.
  3. 그래프의 "근거 충분" 판단(W2.10)에 쓸 점수가 아직 없다.
- **측정 지표**: Recall@10, MRR@10, 질의당 CPU 지연 시간, 모델 다운로드 크기

## Goal

- **해결 목표**: 정답이 후보 안에 있는 문항을 top-10 상위로 올리고, 후속 판단에 쓸 점수를 남긴다.
- **성공 기준(채택 기준)**: 후보별로 아래를 모두 만족하면 채택한다. 둘 다 만족하면 MRR@10이 높은 쪽을 고른다.
  1. MRR@10 **+0.05 이상** (0.458 이상)
  2. 베이스라인보다 첫 정답 순위가 나아진 문항이 나빠진 문항보다 **2개 이상 많음**
  3. Recall@10 **0.733 이상** (회귀 없음)
  4. 질의당 CPU 지연 p95 **3초 이하**
- **기준의 이유**:
  - 조건 2: 문항 하나가 "없음"에서 1위로 오르면 MRR이 0.067 오른다. +0.05만으로는 문항 하나의 우연으로 통과할 수 있다.
  - 조건 4: SPEC §4의 질의 상한은 120초다. 항목 6개 × 검색 3회의 최악 18회를 가정하고 LLM 몫을 뺀 60초를 나눈 값이다. 이 배분은 이 Spec의 가정이다.
- **Out of Scope**: BM25 하이브리드, 메타데이터 머리말, 짧은 표 병합, 임베딩 모델 변경, 그래프 연결과 W2.10 임계값 결정, Docker 이미지 반영, 평가셋 변경, GPU 측정

## What

**Happy Path**

1. 질문마다 e5-small로 회사·연도 필터 안에서 상위 N개를 검색한다.
2. 리랭커가 (질문, 청크 본문) 쌍의 점수를 계산한다.
3. 점수 내림차순, 같으면 `chunk_id` 오름차순으로 정렬한다.
4. 상위 10개를 `retrieved_chunks`로 저장하고 지표를 낸다.
5. 후보 N개 전체의 점수와 지연 시간을 결과 행에 함께 저장한다.

**Edge Cases**

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 후보가 N개보다 적음 | 있는 만큼 재정렬 |
| EC-02 | 필터가 없는 비관련 문항 | 기존처럼 빈 결과, 리랭커를 부르지 않음 |
| EC-03 | 점수가 NaN·Inf이거나 개수가 후보와 다름 | 오류로 중단. 1차 순서로 대체하지 않음 |
| EC-04 | 본문이 512토큰 초과 | `max_length=512`로 절단 |
| EC-05 | 모델이 로컬에 없음 | `local_files_only=True`로 실패, 내려받을 모델 이름을 안내 |
| EC-06 | 점수 동률 | `chunk_id` 오름차순으로 고정 |

## How

### 후보 조사

출처: [bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3), [ko-reranker](https://huggingface.co/Dongjin-kr/ko-reranker), [jina-reranker-v2-base-multilingual](https://huggingface.co/jinaai/jina-reranker-v2-base-multilingual). 크기는 각 저장소 Files 탭의 표시값이다(2026-11-02 확인).

| 항목 | bge-reranker-v2-m3 | ko-reranker | jina-reranker-v2-base-multilingual |
|---|---|---|---|
| 한국어 지원 | 미확인. 카드는 다국어(multilingual)라고만 적음 | 명시(Korean 태그, 한국어 파인튜닝). 학습 데이터는 영문 MS MARCO 번역본 | 미확인. 다국어라고만 적음 |
| 라이선스 | apache-2.0 | 배지 mit. 카드 본문의 MIT 문장은 FlagEmbedding 코드를 가리키며 가중치 라이선스 문장은 미확인 | cc-by-nc-4.0, 카드에 "research and evaluation purposes" 명시 |
| 가중치 | safetensors 2.27 GB | safetensors 2.24 GB | safetensors 557 MB |
| CPU 속도 | 미확인 | 미확인 | 미확인 (GPU 관련 문구만 있음) |
| 입력 길이 | 예제 `max_length=512` | 예제·학습 512 | 최대 1024 명시 |
| 로드 방식 | `AutoModelForSequenceClassification`, 예제에 `trust_remote_code` 없음 | 같음 | 예제 모두 `trust_remote_code=True` |
| 점수 | 원시 logit, sigmoid로 [0,1] | 범위 제한 없음. 예제의 정규화는 후보 목록 내 상대값 | 예제 값 0~1. 변환 방식은 카드 문장으로 단정 불가 |

CPU 속도는 어느 모델도 문서에 수치가 없어 이 프로젝트에서 직접 측정한다. `docs/GATES.md`의 "bge-reranker-v2-m3 약 2.1GB"는 저장소 표시값 2.27 GB와 다르다.

### 설계

- **N = 50.** 30도 Recall 상한은 같지만 1·14번의 첫 정답이 28·29위라 여유가 없고, 이 평가셋에 맞춘 값이 되기 쉽다. 찾을 수 있는 정답 청크도 20개에서 24개로 는다. 점수는 질문과 청크 쌍마다 독립적으로 계산되므로, 같은 실행에서 N=30 결과를 다시 계산 없이 뽑아 참고로 보고한다.
- **구조**: `backend/rag/rerank.py`에 `Reranker` Protocol과 로컬 구현을 둔다. `offline_eval.py`에 리랭커 주입과 CLI 옵션(`--reranker`, `--candidate-k`)을 추가한다. 테스트는 가짜 리랭커를 주입한다.
- **실행 환경**: CPU, `max_length=512`, 배치 크기는 후보별로 같게 고정한다. `HF_HUB_OFFLINE=1`, `local_files_only=True`.
- **지연 시간**: 모델 로딩을 뺀 질의별 시간을 재고, 첫 질의는 워밍업으로 p95에서 제외한다. 같은 PC에서 다른 작업 없이 측정한다.

### 결과 형식

`evaluate_files`가 쓰는 `id`, `retrieved_chunks`는 그대로 두고 필드를 추가한다.

```json
{
  "id": 1,
  "retrieved_chunks": ["chunk-…"],
  "rerank": {
    "model": "BAAI/bge-reranker-v2-m3",
    "candidate_k": 50,
    "latency_ms": 0,
    "candidates": [
      {"chunk_id": "chunk-…", "first_stage_rank": 28, "score": -1.23}
    ]
  }
}
```

- **W2.10용 점수**: 모델의 **원시 점수**를 저장한다. 후보 목록 안에서 정규화한 값은 질문끼리 비교할 수 없어 임계값에 쓸 수 없다. 임계값은 SPEC §5.2대로 모델별 설정값으로 둔다.
- **한계**: 비관련 15문항은 필터가 없어 검색하지 않는다. 그래서 이 실험의 점수만으로는 "근거 없음" 쪽 분포를 알 수 없고, W2.10 임계값을 정하려면 비관련 문항용 필터가 따로 필요하다.

### 제약

- 후보는 모두 로컬 모델이라 외부 API를 부르지 않는다. API 리랭커로 바꾸면 AGENTS.md 규칙 2대로 호출을 `backend/services/llm.py`에만 둔다.
- 동결 평가셋과 `evals/FROZEN.json`은 수정하지 않는다.
- 측정 전에 `evals/PREREGISTER.md`에 기대를 적는다. 1단계 진단 수치는 "사전 등록 전에 이미 본 숫자" 칸에 적는다.
- 재시도나 루프는 두지 않는다.
- 모델 파일, `data/embeddings/`, 청크 파일은 커밋하지 않는다.

### 해석

- **지연이 가장 큰 벽이다.** 쌍당 약 1초다. 3초 안에 들려면 이 PC에서 약 3쌍만 재정렬할 수 있어, 후보 수 조정으로는 풀리지 않는다.
- **나아진 만큼 나빠진다.** 2·5·12·13번은 네 조합 모두 나빠졌고, 6번은 모든 조합에서 top-10 밖으로 밀렸다. 그래서 Recall은 늘어도 MRR은 거의 그대로다.
- **ko가 bge보다 낫다.** 같은 입력에서 MRR이 0.05~0.08 높다. 표본이 15문항이라 문항 1개가 Recall 0.067을 움직인다.
- **합치기와의 결합은 10번을 살렸지만 대가가 있다.** 10번이 두 모델 모두 2위로 올랐다. ko에서는 14번을 잃어 Recall은 그대로다.

### 측정 검증

- bge 모델 카드 예제의 점수 `[-8.1875, 5.26171875]`와 이 구현의 값 `[-8.184, 5.265]`의 차이가 0.004 이내다. 모델 로드에 경고가 없었다. ko-reranker는 같은 예제에서 관련 문장 5.49, 무관한 문장 -4.44로 방향이 맞다.
- 2번 문항의 후보 50개를 두 모델로 다시 계산해 저장값과 최대 차이 0.0을 확인했다.
- 지표 파일의 `dataset_sha256`은 5번 `8f79a754…`(동결), 6번 `ea83f2af…`(파생)다.
- AC-RR-07: Recall@10이 상한(0.867, 0.933)을 넘지 않는다.
- 전체 재실행은 하지 않았다. 지연은 이 PC의 한 번 측정값이다.

## AC (Given-When-Then)

**AC-RR-01 · 재정렬**
- GIVEN: 후보 3개와 1차 순서를 뒤집는 점수를 주는 가짜 리랭커
- WHEN: 재정렬 실행
- THEN: `retrieved_chunks`가 점수 내림차순이고, 후보 집합은 그대로다

**AC-RR-02 · top-10 절단과 점수 저장**
- GIVEN: 후보 50개
- WHEN: `--top-k 10 --candidate-k 50`으로 실행
- THEN: `retrieved_chunks`는 10개, `rerank.candidates`는 50개이고 각 항목에 `chunk_id`, `first_stage_rank`, `score`가 있다

**AC-RR-03 · 동률 고정**
- GIVEN: 점수가 같은 후보
- WHEN: 재정렬을 두 번 실행
- THEN: 순서가 `chunk_id` 오름차순으로 같다

**AC-RR-04 · 잘못된 점수 거부**
- GIVEN: NaN을 내거나 개수가 틀린 가짜 리랭커
- WHEN: 재정렬 실행
- THEN: 오류로 중단하고 결과 파일을 쓰지 않는다

**AC-RR-05 · 비관련 문항**
- GIVEN: 필터가 없는 비관련 문항
- WHEN: 실행
- THEN: 리랭커를 호출하지 않고 빈 결과를 남긴다

**AC-RR-06 · 지표 호환**
- GIVEN: 리랭커 결과 파일
- WHEN: 기존 `evaluate_files`로 채점
- THEN: 추가 필드가 있어도 Recall@10·MRR@10이 계산되고, 리랭커 없이 실행한 결과는 기존 `diag`·`emb` 결과와 지표가 같다

**AC-RR-07 · 상한**
- GIVEN: 진단 결과
- WHEN: 리랭커 Recall@10을 계산
- THEN: 값이 0.867을 넘지 않는다. 넘으면 후보 범위 오류로 본다
