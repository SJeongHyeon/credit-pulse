# AI 코딩 도구 사용 기록

제출물입니다. 어떤 도구를 어디에 어떻게 썼고, **그 결과를 어떻게 검증했는지**를 적습니다. 쓰지 않았다고 감점되지도, 많이 썼다고 가산되지도 않습니다. 기록이 정직한지가 중요합니다.

아래는 박민영이 Claude Code로 맡긴 일 중 결과 기록이 남은 것이다. 다른 조원의 사용 기록은 각자 행을 더한다. **류승민·서정현의 두 행(Codex)은 11/17 밤에 박민영이 저장소의 기록(포트폴리오, 브랜치 이름, 증거 문서)에서 옮겨 적은 것이고 본인이 확인하지 않았다.** 'AI가 틀린 곳' 칸은 본인만 알 수 있어 비워 두었다.

## 도구에게 일을 시킬 때 지킨 규칙

- **Spec 먼저**: 기능은 `docs/specs/{기능}.md`(Why·Goal·What·How·AC)를 먼저 쓰고 사람이 본 뒤에 구현을 시켰다(AGENTS.md). 검색·그래프를 바꾸는 일은 `evals/PREREGISTER.md`에 기대를 숫자 범위로 먼저 적었다.
- **확인 먼저**: 파일 덮어쓰기·삭제, 여러 파일 동시 수정, 패키지 설치, 커밋·push는 실행 전에 사람에게 물어보게 했다(개인 지침). 운영 DB 적재와 운영 환경변수 변경은 AI가 실행하지 않고 명령만 받아 사람이 실행했다. 비교·시연 스크립트는 주소에 `supabase`가 들어 있으면 실행을 거부한다.
- **동결 평가셋 수정 금지**, LLM 호출은 `backend/services/llm.py`에서만, 비밀값은 `.env`에만(AGENTS.md). 커밋 메시지와 PR에는 AI 표기를 넣지 않았다.
- **시험이 진짜 잡는지 확인**: 시험 통과만으로 완료라고 받지 않았다. 코드를 일부러 망가뜨려 시험이 실패하는지 본 변이 확인을 GATES에 남겼다.
- **모르는 라이브러리 동작은 문서나 코드로 확인**: psycopg `prepare_threshold`, psycopg 3.3의 autocommit 연결에서 `transaction()`이 BEGIN을 보내는지, pgvector HNSW 필터링 순서 등은 추측하지 않고 문서와 라이브러리 코드를 읽게 했다.

## 가장 크게 틀렸던 사례 1개

**운영 반영 명령을 셸 종류를 틀려 안내했고, 그 결과 환경변수 없이 운영에 배포됐다(11/7).**

- **무엇을 시켰나**: Supabase 적재부터 Cloud Run 재배포까지, 사람이 직접 실행할 명령을 순서대로 달라고 했다.
- **어떻게 틀렸나**: AI가 PowerShell 문법 명령(`$env:…`, 경로의 `\`, 줄 끝 `` ` ``)을 주면서 "앞에 `!`를 붙여 실행하면 결과를 바로 본다"고 안내했다. 그런데 Claude Code의 `!`는 bash로 실행된다. 그래서 환경변수 설정과 적재 명령은 모두 실패했다. `gcloud run deploy`만 실행됐는데, bash가 `` ` ``를 명령 치환으로 읽어 `--update-env-vars` 줄이 통째로 빠졌다. 결과적으로 **커밋하지 않은 작업본 코드가 새 환경변수 없이 운영에 올라갔다.**
- **어떻게 알아챘나**: 명령 출력의 `command not found` 줄들을 AI가 읽고 원인을 설명했다. 그다음 읽기 전용 명령(`gcloud run services describe`, `/health`)으로 운영 상태를 확인했다. `VECTOR_BACKEND`가 없어 기본값 memory로 돌고 있었고 메모리 설정도 유지돼 있어서, 검색 동작은 배포 전과 같았다.
- **피해와 조치**: 서비스 장애는 없었다. 하지만 git에 없는 코드가 운영에 있었으므로 바로 커밋해 맞췄다. 이후로는 비밀값이 든 명령은 '따로 연 PowerShell 창'에서, 비밀값 없는 한 줄 명령만 `!`로 실행하게 안내했다. 이 함정은 README 배포 절에 적었다.
- **배운 것**: AI가 준 명령은 '어느 셸에서, 어디에 실행되는가'까지 확인해야 한다. 운영을 바꾸는 명령은 한 번에 하나씩 실행하고 결과를 본 뒤 다음으로 넘어간다.
