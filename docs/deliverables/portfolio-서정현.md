## 숫자로 보이는 결과

[EVAL_REPORT](../../EVAL_REPORT.md)(동결 평가셋 v2: 관련 25 · 비관련 25)와 아래 링크한 증거 문서에 있는 숫자만 적었다. 팀 전체 점수가 아니라 **내가 바꾼 것 하나하나의 전후**다.

- **평가 지표 5개를 정의하고 계산기를 만들었다.** 정답 근거 인용·오답 근거·과잉 거절·올바른 거절·환각 위험을 따로 보고하고 하나의 정확도로 합치지 않는다(2장). 이 지표로 잰 단일 에이전트 첫 기준 점수는 검색 Hit 1.000인데 환각 위험 14/25, 올바른 거절 11/25였고(4-1), 실패 21건의 갈래가 라우팅 16·작성 5·검색 0으로 나와 검색보다 라우팅·작성을 먼저 고치게 됐다.
- **인용 검증 verifier**: 숫자가 인용 청크에 없는 오답 근거 1건(63번)을 의도대로 걸렀다. 대가로 정답 근거 1건(3번)이 줄었는데, 원인이 verifier인지 작성기 흔들림인지는 가르지 못했다고 적었다(4-3).
- **벡터 검색이 지는 질문 유형을 정의하고 문서 구조 그래프로 재 봤다**(4-55). 일상어로 묻는 표 항목 질문 23건에서 첫 검색 Hit@10 19/23 → **20/23**(60번 회수, 원문 대조로 당기 표가 맞음을 확인). 그러나 동결 v2의 62번이 정답 → 오답 근거로 바뀌고(24/0 → 23/1) 검색 노드 p95가 1,984 → 2,765ms로 늘어 **기본 꺼짐으로 두었다.**
- **목차 어휘 질의 번역**(4-56): 모델이 용어를 추측하게 한 앞선 실험은 0/4였는데, 그 회사 보고서의 **항목 이름 목록에서 고르게** 하자 일상어 Hit@10 20/23 → **22/23**, 정답 / 오답 인용 18 / 4 → **20 / 1**. 검색 단계 p50이 +2.3초(한도 +1.5초)라 **미채택**. 선택 모델을 gemini-3.5-flash-lite로 바꿔도 비용만 $0.262 → $0.170으로 줄고 p50 +2.05초가 남아 다시 미채택(4-57).
- **그래프 후보·리랭커 입력 줄이기**(11/17): 리랭커 입력 글자를 약 18% 줄였지만(일상어 1,049,089 → 864,036자, 동결 v2 1,612,699 → 1,323,354자) 검색 노드 p95는 일상어 3,854 → 3,860ms, 동결 v2 4,051 → 4,280ms로 같거나 늘었다. 이웃 탐색 자체는 중앙값 **0.0052ms**라 지연 원인이 아님을 1,160회 재생으로 확인했고, 외부 임베딩·리랭커 호출 시간을 따로 기록하게 해 다음 측정에서 분리할 수 있게 했다([증거](../evidence/graph_latency_diagnosis_2026-11-17.md)). 속도가 빨라졌다고 주장하지 않는다.
- **거절 뉴스의 회사 혼입 제거**(측정 18개 질문, HUB 18회, [증거](../evidence/news_company_filter_2026-11-12.md)): 한화시스템 노조 질문에서 한화오션 기사 3건 → **0건**, 제목·요약 회사명 포함률 88.9% → 100%(구조상), 평균 반환 4.78건, 0건 질문 0/18. 정렬은 최신순 → '관련도순 20건 중 최근 90일, 날짜순 5건'으로 바꿔 제목 회사명 포함률 17.5% → 45.0%, 최근 90일 비율 100%(질문 8개, [증거](../evidence/news_sort_measure_2026-11-12.md)).
- **계정 분리**: 배포 주소에서 계정 2개로 심사 건(양방향 404)과 규칙(Store)이 서로 보이지 않음을 확인([증거](../evidence/f3_account_isolation_2026-11-10.md)).
- **리랭커 후보 수·배치 크기(로컬 CPU)**: 후보 10·20·50개와 batch 8·16·32를 재 봤고 p95가 8.12~44.83초라 3초 기준을 모두 넘었다(3장 10-A·10-B). 이후 검색 조합은 API 리랭커(Voyage rerank-2.5, p95 0.66~0.83초)로 정해졌다(3장 53·55번).

## 내가 내린 판단과 그 이유

- **효과가 있어도 사전 등록한 기준을 못 넘으면 버렸다(목차 어휘 번역, 4-56·4-57).** 놓친 3건 중 2건을 되찾고 오답 인용도 줄었지만, 질문마다 LLM 호출 한 번이 직렬로 앞서 p50이 한도를 넘었다. 측정 뒤에 한도를 늘리지 않았고, 모델을 바꿔 다시 쟀지만 구조의 하한(약 2초)이 남는다는 것까지 적었다.
- **그래프 검색을 켜지 않았다(4-55).** 한 건(60번)을 되찾았지만 근본 원인인 용어 불일치는 풀지 못해 4건 중 3건은 그대로였고, 동결 v2에서 한 문항이 나빠졌다. 이 그래프는 DART 원문의 연속 청크를 잇는 제한적 문서 그래프이며 Microsoft GraphRAG(개체 추출·커뮤니티 요약)가 아니라고 문서에 못 박았다. 후보 상한 1, 기존 후보 40개, 저점수 재검토 같은 옵션도 같은 이유로 전부 기본 꺼짐이다.
- **상한을 낮추는 쉬운 길을 막았다.** RRF 후보 50 → 40으로 줄이면 빨라질 것 같았지만, 키 없이 저장된 기록을 재생하니 23/23 문항에서 상위 40개의 순서나 구성이 달라졌다. 일반 후보 40 → 30도 31~40위에 정답 청크가 있는 문항이 있어 적용하지 않았다.
- **측정이 틀렸을 때 숨기지 않고 정오표를 남겼다.** 뉴스 정렬 측정에서 'C안'이 후보 20건을 5건으로 자르는 결함으로 사실상 B에 90일 필터를 건 값이 나왔다. 첫 결과는 판정에 쓰지 않고, 결함을 고친 뒤 재측정했다. 회사명을 쪼개지 않는 방식(P)과 큰따옴표(Q)는 두 번 모두 기준 미달이었고, '원인 가설이 틀렸다'고 기록한 뒤 검색어는 두고 결과를 거르는 사후 필터로 바꿨다.
- **측정하지 않은 것은 측정했다고 쓰지 않았다.** 인젝션 3겹 방어는 키 없는 오프라인 시험(질문 가드 시나리오 12건 기대 일치, 평가셋 질문 전체에서 신호 0건, 악성 규칙 10종 거절·정상 규칙 7종 통과, 비밀 7유형·프롬프트 지문 11개 탐지)으로만 확인했고, **실제 모델 재측정과 평가셋 점수 재측정은 하지 않았다.** EVAL_REPORT 6장에 '코드와 오프라인 시험 기준으로 동작한다'까지만 말할 수 있다고 적었다. 거절 뉴스 분기도 동결 v2 50건 응답 지표 측정은 돌리지 않았고(PREREGISTER 118번), 뉴스 선별 측정만 질문 8~18개 표본으로 했다.
- **새 기능은 기본 꺼짐으로 먼저 넣었다.** 뉴스 검색·그래프 검색·질의 번역 모두 플래그로 서비스 연결 전에 코드를 넣고, 측정이 기준을 넘은 뒤에만 연결했다(회사명 사후 필터만 채택·연결).
- **같은 사람이 질문을 쓰고 정답을 판정하지 않게 나눴다.** 질문은 내가, 정답 청크 판정은 류승민이, 결과 검토는 박민영이 맡았다(SPEC §7). 질문 작성자는 정답 청크를 열람하지 않는다.

## AI 코딩 도구 사용 기록

**Codex와 Claude Code**를 번갈아 썼습니다. Codex는 문서 구조 그래프 검색과 시장 근거 조사에, Claude Code는 화면, 가입, 인젝션 방어, 거절 뉴스, 질의 번역 실험에 주로 썼습니다. 모든 실험은 사전 등록한 기준으로 판정했고, 도구가 틀린 곳(뉴스 키 발급 경로, 정렬 측정 결함)은 기록에 남겼습니다. 인젝션 방어는 실제 모델 재측정을 하지 않았다고 적었습니다. [서정현 AI 도구 사용 기록](ai_tools_log.md#서정현-ai-도구-사용-기록)
